# Archive Center 3.1–3.5 통합 릴리스 안내

상태: 3.5.0 누적 릴리스 정본  
정리일: 2026-07-28  
적용 범위: Archive Center 3.1, 3.2, 3.3, 3.4, 3.5

## 소개

Archive Center 3.5는 3.1부터 이어진 원작 자료 관리, Source Discovery, RisuAI 입력
근거 추적, 장기 기억 전달 정밀화와 작업 진행 HUD를 하나의 배포판으로 묶은 누적
릴리스다.

이번 릴리스의 중심은 기억을 무조건 많이 넣는 것이 아니다. 현재 사용자 입력과
장면에 연결된 자료를 선택하고, 원문·요약·직접 근거·관계·상태·비밀 보호의 소유권을
분리하며, 실제 RisuAI 요청에 무엇이 적용됐는지를 추적하는 것이다. MariaDB는
canonical truth를, ChromaDB는 재구축 가능한 벡터 검색을 담당한다. `Archive Center.js`는
RisuAI 관찰·전송·실제 payload 적용·UI만 맡고 정책과 저장 판단은 Go backend가 맡는다.

3.1–3.5의 기존 장문 작업 문서는 이 문서로 통합한다. 아래의 `완료`, `구현됐으나
추가 검증 필요`, `3.6 이후 인계` 구분이 릴리스 시점의 정본이다.

## 버전별 누적 내용

### 3.1 — Canon Pack과 원작 자료 소유권

- 작품·판본·continuity identity와 제목·원제·번역명·별칭 검색을 도입했다.
- Canon Pack ZIP을 설치 전에 manifest와 checksum으로 검증한다.
- 설치·활성화·비활성화·제거·이전 generation rollback을 Go와 MariaDB가 처리한다.
- 공용 Canon Pack, 사용자 비공개 원문, Local Canon Overlay와 승인 전 candidate를
  서로 다른 소유권으로 보존한다.
- source observation, 문서 hash, evidence locator, conflict, uncertainty와 coverage를
  함께 추적한다.
- 같은 자료를 중복 저장·주입하지 않되 독립 출처의 provenance는 잃지 않는다.

### 3.2 — Source Discovery와 원작 자료 UI

- 허용된 공개 출처를 대상으로 한 Source Discovery, safe fetch, redirect·MIME·크기·
  timeout·SSRF 제한을 구현했다.
- 수집 원문을 로컬 DB에 보존하고 문서별·통합 분석, 이어 분석, 누락 section 복구와
  분석 대기열 상태를 제공한다.
- entity, world rule, timeline event, relation과 fact를 근거에 연결된 pending candidate로
  분리한다.
- 중복·mirror·저가치 결과, 잘못된 구조 후보와 외부 metadata 오탐을 줄였다.
- 원작 자료 탭에서 작품, 원문 문서, 후보, 진행 상태, Canon Pack과 검색 설정을 관리한다.
- 원문 전체와 사용자 보유 자료는 로컬에만 남으며 릴리스에 포함되지 않는다.

### 3.3 — 현재 입력과 source lifecycle 정합성

- RisuAI `input`, `beforeRequest`, `afterRequest`, active chat과 표시 결과를 서로 다른
  lifecycle 관찰로 취급한다.
- 사용자 원문과 prefill·메타 입력을 구분하기 위한 source observation 계약을 Go에
  연결했다.
- streaming candidate를 canonical final로 먼저 저장하지 않고 실제 active final 확인을
  기준으로 저장한다.
- 복사·재시작·세션 재연결에서 잘못된 turn offset과 다른 CID 재사용을 차단하는
  session/source fence를 강화했다.
- 원문 저장을 평론가 파생 처리보다 먼저 수행하고 긴 timeout 또는 client 취소에서도 raw
  user/assistant 보존을 우선한다.
- 사용하지 않는 Table Read UI·저장 ledger·backend route를 제거했다.
- guide OFF에서는 출력 가이드와 관련 canonical 변화가 없어야 한다는 parity 경계를
  고정했다.

### 3.4 — 관련 기억 선택과 독립 예산

- 메인 기억을 다음 일곱 delivery class로 분리했다.
  1. 사건·최근 기억
  2. 인물 객관 상태
  3. 인물별 주관 기억·관계
  4. 물건·장소·세계 상태
  5. 비밀·정체 보호
  6. 미해결 목표
  7. 직접 근거
- Go의 `memory_delivery_plan.v1`이 자료별 예약량·사용량·미사용량·보류량과 최종
  순서·본문을 결정한다.
- 비밀 보호 지침을 실제 기억과 분리하고 비밀 원문, 소유자의 비공개 감정과 지식 경계를
  일반 사실로 노출하지 않는다.
- 예산을 채우기 위해 무관한 오래된 기억을 끌어오지 않는다. 관련 자료가 부족하면 공간을
  비워 둔다.
- episode 요약·핵심 사건, 직접 근거·상태·세계 규칙의 중복과 빈 구조를 줄였다.
- 과거 사용자 입력을 현재 명령처럼 다시 전달하지 않고 직전 완료 턴은 작은
  `Input Context`가 한 번만 소유한다.
- 실제 Host system constraint와 현재 사용자 입력을 `response_execution_contract.v1`로
  연결하고 서사 안내 예산을 장기 기억·원작 자료 예산과 분리했다.

### 3.5 — 출력 충실성 계보와 진행 HUD

- 평가 corpus, source-to-final lineage와 guide efficacy/no-forced-difference 회귀 시험을
  추가했다.
- Host observation, 기억 source, payload 적용과 final 표시를 같은 request correlation로
  연결했다.
- 실제 outbound payload 확인이 맞지 않으면 사후 조립값을 생성 전 최종 입력으로
  표시하지 않는다.
- Direct Evidence의 3.0 기준 동작을 복구했다. 요청 단위 약한 관계 링크와 graph traversal은
  3.5에서 제거하고 4.6으로 이관했다.
- RisuAI 우측 플로팅 HUD에 현재 턴, 처리 순서, LLM 호출과 초 단위 경과 시간, 원문 저장,
  요약·직접 근거·관계·상태 등 생성 수, 단계별 성공·건너뜀·경고·실패를 표시한다.
- HUD는 작은 반투명 패널이며 완료 결과를 눌러 닫을 수 있다. 설정에서 완전히 끌 수 있다.
- 오류는 일반 경고와 구분된 붉은 상태로 표시한다.

## 구현됐으나 추가 검증이 필요한 부분

다음 항목은 production source와 자동 시험이 존재하지만 모든 실사용 조건을
`release_gate_verified`로 닫은 것은 아니다.

- Canon Pack lifecycle과 Source Discovery는 local/disposable MariaDB 및 자동 회귀를
  통과했지만 여러 실제 작품·판본·publisher와 외부 provider 조합의 장기 운영 증거가
  제한적이다.
- 메인 기억 일곱 예산, 장면 관련성, 비밀 보호와 과거 입력 권한 차단은 실제 입력 확인과
  자동 시험을 거쳤지만 200·300턴 장기 세션, 재시작, 리롤, 삭제, 분기와 vector 장애를
  모두 묶은 실사용 matrix는 남아 있다.
- source lifecycle과 active-final 교체 fence가 구현됐지만 RisuAI/PocketRisu의 모든
  reroll·branch·edit 조합을 실제 Host에서 반복 검증하지 않았다.
- 3.5 HUD의 일반 성공·경고·오류·닫기·사용 안 함은 확인했지만 reroll 도중의 supersede
  표시와 모든 provider 실패 조합은 아직 전수 확인하지 않았다.
- Linux, macOS와 Termux 패키지는 cross-build와 package 검사를 수행한다. 실제 각 OS
  장치의 설치·업데이트·복구 전체 증거는 별도 release gate다.

보존하며 뒤 버전의 상세 계획을 중복 정의하지 않는다.

## 배포 패키지와 사용자 데이터

3.5.0 릴리스는 다음 패키지를 제공한다.

- Windows x64 자동 설치 패키지
- Windows x64 경량 업데이트 패키지
- Linux x64 및 arm64 자동 설치 패키지
- macOS Intel 및 Apple Silicon 자동 설치 패키지
- Android Termux arm64 자동 설치 패키지
- 전체 자산 SHA-256 목록

릴리스에는 `.env`, `.env.full.local`, MariaDB·SQLite DB, ChromaDB persist data,
사용자 원문, 채팅, API key, cache, log와 runtime state를 포함하지 않는다. 패키지는
검토된 example 환경파일만 제공하며 기존 설치를 업데이트할 때 사용자 설정과 DB를
덮어쓰지 않는다. Windows 자동 설치판도 MariaDB·Python·ChromaDB 실행물을 동봉하지
않는다. full-local profile의 첫 실행은 공식 MariaDB와 CPython을 내려받아
SHA-256/서명 검증 후 사용자 전용 runtime 경로에 설치하고, 고정 ChromaDB 버전을
별도 virtual environment에 설치·검증한다. `core_lite`/`fallback` profile이나 외부
Chroma endpoint를 선택하면 로컬 ChromaDB는 필수가 아니다. 이 설치 보완은 3.5.0
최초 태그 이후의 관리형 패키지 유지보수 이력이며
[`3.1-3.6-e-implementation-ledger.md`](3.1-3.6-e-implementation-ledger.md)에 커밋별로
기록한다.

## GitHub 릴리스 소개문

Archive Center 3.5는 3.1부터 진행한 원작 자료 관리와 Source Discovery, 3.3의
RisuAI source lifecycle 정합성, 3.4의 장면 관련 기억·독립 예산, 3.5의 출력 충실성
계보와 플로팅 진행 HUD를 하나로 묶은 누적 릴리스입니다.

원작 자료는 Canon Pack과 사용자 로컬 자료의 소유권을 분리해 관리하고, 기억은 현재
장면과 연결된 항목만 자료 종류별 예산 안에서 전달합니다. RisuAI 화면에서는 현재 턴,
LLM 호출 시간, 저장·요약·직접 근거·관계·상태 생성 결과를 작은 HUD로 확인할 수 있으며
설정에서 끌 수 있습니다.

Windows, Linux, macOS와 Android Termux용 패키지를 제공합니다. 사용자 `.env`, API key,
DB, ChromaDB 데이터와 개인 원문은 릴리스에 포함되지 않습니다.

관계 graph UI, 응답 후 파생 기억 비동기화, 장기 세션·reroll 전체 matrix와 일부 진단
보존 작업은 3.6 이후 단계로 분리했습니다.
