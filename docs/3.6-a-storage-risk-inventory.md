# Archive Center 3.6-A — 현재 저장 구조와 위험 고정

상태: `source_characterized`  
범위: 현행 production owner와 저장 형태 조사, 특성 테스트, 3.6-B 진입 조건 고정  
비범위: 운영 스키마 변경, 사용자 DB 읽기·쓰기, 데이터 migration, LLM·prompt·recall·budget 변경, 자동 entity merge

## 1. 이 단계가 하는 일

3.6-A는 현재 잘 작동하는 저장 경로를 새 구조로 바꾸는 단계가 아니다. 3.6-B 이후의 stable entity ID와 speaker attribution 작업이 기존 원문 저장, 재처리, 삭제·리롤, 벡터 복구를 망가뜨리지 않도록 현재 production 경로와 알려진 공백을 먼저 고정한다.

이번 구현은 다음 두 종류의 증거만 추가한다.

1. 현재 동작을 그대로 호출하는 Go 특성 테스트
2. 어떤 owner와 row를 이후 migration이 보존해야 하는지 적은 이 문서

`Archive Center.js`, Go production code, `migrations/001_schema.sql`, 실제 MariaDB/Chroma 데이터에는 변경이 없다.

## 2. 현행 production 경로

| 단계 | production owner | 현재 결과 | 3.6 이후 보존 조건 |
|---|---|---|---|
| 완료 턴 수신과 원문 저장 | `internal/httpapi/group_turn_complete.go` | user/assistant raw chat log를 먼저 저장하고 Critic extraction으로 진행 | 원문은 파생 기억 성공 여부와 무관하게 보존 |
| Critic 결과 저장 | `internal/httpapi/turn_extraction_persist.go`의 `saveCriticExtractionArtifacts` | turn summary, direct evidence, KG, entity/state 등으로 분기 저장 | 모든 파생 row가 동일한 root source revision을 추적 |
| 인물·상태 저장 | `internal/httpapi/turn_extraction_character_state.go` | 이름 문자열을 기준으로 entity와 character state 저장 | stable entity ID와 namespace가 이름과 분리 |
| 이름 정규화 | `internal/httpapi/turn_extraction.go`의 `canonicalCharacterName` | alias key와 편집거리로 기존 이름을 선택 | 유사 이름이나 단일 모델 판단만으로 merge 금지 |
| confirmed alias 반영 | `internal/httpapi/turn_extraction_private.go`의 `applyConfirmedIdentityAliasCanonicalMerge` | Critic의 confirmed alias map을 extraction 전체에 반영 | source-linked proposal/review와 mapping revision 필요 |
| 벡터 기록 | `internal/httpapi/turn_extraction_vector.go` | DB row 저장 뒤 Chroma upsert, 실패 시 DB row와 경고를 남김 | transaction 밖 vector 작업은 durable outbox와 재생 계약 필요 |
| 재처리 | `internal/httpapi/group_admin_rescan.go` | canonical chat log를 다시 Critic에 보내 동일 saver 호출 | source revision + derivation version 기반 idempotent job 필요 |
| source 활성 판정 | `internal/httpapi/complete_turn_source_acceptance.go` | active/superseded/deleted 상태와 stale commit fence 판정 | 파생 row의 typed source FK와 commit-time revision 비교 필요 |
| 유지보수 요청 | `internal/httpapi/group_admin.go` | 현재 `shadow_only`, audit 기록만 수행 | 실제 재처리 worker로 오인하지 않음 |
| 리롤·삭제 | `internal/store/mariadb_logical_turn_replace.go`, rollback 경로 | turn 경계로 파생 row와 벡터를 정리 | dependency graph 도입 전 기존 광역 삭제 의미 보존 |

JavaScript는 이 경로의 정책 owner가 아니다. RisuAI의 실제 표시·삭제·리롤 관찰과 HUD/DOM만 담당하며, 3.6의 identity/admission/migration 판단은 계속 Go가 소유한다.

## 3. 현행 row와 source 연결 상태

| row | 현재 식별·source 정보 | 고정된 공백 |
|---|---|---|
| `chat_logs` | session, turn, role, content | message/generation/branch/revision을 직접 보유하지 않음 |
| `memories` | session, turn, aggregate summary JSON | root source FK, speaker ID, branch/revision, atomic kind 없음 |
| `direct_evidence_records` | source turn range, message IDs JSON, source hash, lineage, tombstone/supersession | 가장 강한 source spine이나 다른 파생 row가 이를 typed FK로 참조하지 않음 |
| `kg_triples` | 문자열 subject/predicate/object, source turn | subject/object entity FK와 source revision 없음 |
| `entities` | DB auto ID, name, type, aliases JSON, first/last turn | stable identity ID의 의미·namespace·identity lifecycle·source revision 없음 |
| `character_states` | character name, turn, 상태 JSON | character entity FK와 source revision 없음 |
| `character_events`, `trust` | character/target 이름 문자열과 source turn | 동명이인·namespace를 안전하게 분리할 stable pointer 없음 |

결론: 기존 JSON과 이름 문자열만으로는 동명이인, 복수 화자, branch/source revision, invalidation을 FK와 hard filter로 보장할 수 없다. 따라서 3.6-B/C의 요구사항을 충족하려면 normalized additive migration이 필요하다. 실제 스키마와 데이터 migration은 3.6-A가 아니라 후속 packet에서 수행한다.

## 5. 회귀 증거

3.6-A가 재사용하는 기존 production-path 회귀 증거:

- 동일 턴 memory 중복 방지: `TestCompleteTurnMemorySameTurnRegenerationSkipsDuplicateInsert`
- 동일 턴 evidence/KG 중복 방지: `TestSaveCriticExtractionArtifactsSkipsDuplicateEvidenceAndKGForSameTurn`
- confirmed alias canonical merge: `group_turn_part13_test.go`의 `confirmed_identity_alias_canonicalizes_saved_artifacts_without_rewriting_raw_evidence` 하위 테스트
- raw turn 재처리: `TestAdminRescanRegeneratesMissingArtifactsFromRawTurn`
- 긴 session 재처리와 중복 방지: `TestAdminRescanLongSessionResumesFromTurnZeroThrough120WithoutDuplicates`
- active/superseded/deleted source fence와 리롤: `complete_turn_source_acceptance_test.go`
- 실제 리롤 row/vector 정리: `TestCompleteTurnRerollReplacesCanonicalTailAndDeletesSupersededVector`
- 유지보수 shadow-only 상태: `TestMaintenanceEnqueueShadowWritesAuditAndTrace`
- rollback 삭제 경로: `group_turn_part08_test.go`, `internal/store/mariadb_rollback_test.go`
- vector drift/reindex 복구 표면: `group_admin_part02_test.go`, `group_admin_part03_test.go`

특성 테스트 파일은 `internal/httpapi/precision_memory_inventory_test.go`이다. 테스트는 fake/disposable store만 사용하며 외부 provider, MariaDB, Chroma에 연결하지 않는다.

## 6. 검증 수준과 미확인 항목

현재 증거 수준:

- source owner inventory: 확인
- fake store를 통한 production saver/name resolver 호출: 확인
- 기존 Go 회귀 테스트: 실행 결과를 이 문서와 함께 기록
- 실제 사용자 DB: 접근하지 않음
- 지원 MariaDB clone에서 schema upgrade/rollback: 3.6-A에서는 실행하지 않음
- 실제 Chroma 장애·재시작·outbox 복구: 아직 구현 전
- live RisuAI의 복수 화자/동명이인 end-to-end: 아직 구현 전

따라서 `source_characterized`는 3.6-B 설계를 시작할 수 있다는 뜻이지, 새 저장 구조나 migration이 실 DB에서 검증되었다는 뜻이 아니다.

## 7. 3.6-B 진입 조건

3.6-B는 다음 경계를 넘지 않는 bounded packet으로 시작한다.

1. `entity_identity.v1`의 stable backend ID, namespace, lifecycle, source binding을 additive schema로 정의한다.
2. display name과 alias는 identity가 아니라 source-linked surface로 저장한다.
3. 같은 이름, 유사 이름, 공용 alias, session/Host/reference namespace를 자동 merge하지 않는다.
4. speaker attribution이 불명확하면 `unknown/tentative/needs_review`와 원문 span을 보존한다.
5. 기존 name-based row는 바로 삭제하거나 덮어쓰지 않고 stable ID projection과 비교한다.
6. migration은 clone/dry-run, row/vector/projection 대조, rollback 증거가 준비되기 전 실제 사용자 DB에 적용하지 않는다.
7. 3.6-B가 완료되면 이 문서의 `36A-R2`, `36A-R3` 특성 테스트를 새 positive/negative identity 계약 테스트로 교체한다.

## 8. 3.6-B 후속 상태 — 2026-07-28

3.6-B source 구현으로 `36A-R2`와 `36A-R3`의 production 위험은 다음과 같이
교체됐다.

- `36A-R2`: `canonicalCharacterName`의 편집거리 fuzzy merge를 제거하고
  `Test36BNearNameCanonicalizationDoesNotCollapseDistinctPeople`로 반대 계약을 고정했다.
- `36A-R3`: legacy name row를 삭제하지 않은 채 `entity_identities`,
  `entity_identity_surfaces`, `entity_identity_artifact_bindings`,
  `speaker_attributions`를 additive projection으로 연결했다.
- 동명이인, 동일 source replay, session/reference namespace 격리, ambiguous speaker raw
  span, same-turn KG/state binding은 `entity_identity_test.go`에서 검증한다.
- fresh schema와 기존 DB compatibility migration은
  `entity_identity_schema_test.go`에서 같은 필수 테이블·필드를 검사한다.
- turn rollback, logical tail replacement, session deletion, admin reset은 identity FK
  순서 삭제를 포함한다.

`36A-R1`은 3.6-C의 precise row로 병렬 완화됐고, `36A-R4`·`36A-R7`은 3.6-D의 accepted
source revision·precise dependency·invalidation/outbox로 병렬 완화됐다. 기존 aggregate
writer와 source FK가 없는 과거 projection의 공통 admission 전환은 3.6-E의 미완료 위험으로
유지한다. 이번 source
회귀 통과는 실제 사용자 DB migration, disposable MariaDB clone upgrade/rollback,
live RisuAI 복수 화자·reroll 검증을 대신하지 않는다.
