# Archive Center 4.0 Memory Restoration Work Contract

Status: mandatory read-before-work contract
Scope: 4.0 memory creation, MariaDB persistence, embedding, retrieval, injection,
lorebook reference, and edit-check display
Recorded baseline: 2026-08-13

## Product Goal

The goal is better roleplay and story continuity, not the maximum number of
guards or perfect certainty.

Archive Center 4.0 must preserve the broad and understandable memory behavior
of 3.9.11 while retaining the 4.0 work that has a reproduced user benefit:

- retain the full Critic extraction as canonical MariaDB memory;
- prevent one private item from deleting or suppressing the whole turn memory;
- generate understandable semantic embedding text for events, relationships,
  habits, profiles, and voice;
- keep aggregate Event memory retrieval separate from typed support vectors;
- prevent current-turn, deleted-generation, and reroll self-reentry;
- reference lorebooks only when activated and keep them in their own lane;
- show memory delivery classes separately in Edit Check;
- keep explicit private ownership out of the general public lane without
  deleting the canonical memory or the private typed memory.

This work is not a project to make memory perfectly proven. Minor duplication,
uncertain but understandable surrounding memory, and broad candidate collection
are preferable to silently deleting useful RP continuity.

## Stage 1 Read-Only Findings

No runtime file, database, or package was changed during Stage 1.

### Keep: 3.9.11 behavior

- `buildPreciseMemoryUnitsFromExtraction` still requires an exact unique source
  span and accepted Direct Evidence for quote-grade precise units. This is the
  same in 3.9.11 and current source. It must not be confused with aggregate
  `Memory.SummaryJSON` storage.
- The existing scene/entity relevance check in general selection is inherited
  from 3.9.11. Do not remove it without a reproduced
  `vector_scope_rejected` failure proving that it caused a missing memory.
- Broad semantic candidates must not be deleted merely because they are not
  authoritative typed current-state facts.

### Keep: required 4.0 behavior

- The whole-turn `memoryAdmissionHasPerspectiveScopedContent` sentinel path is
  removed. Do not restore the behavior that stored every mixed turn as
  `perspective_scoped_typed_delivery` with no aggregate vector.
- `buildPublicMemoryProjection` keeps the canonical full extraction and creates
  the general-search copy. Explicit private buckets or explicitly private items
  are separated at item level; they must not taint the whole row.
- The aggregate-memory `tier=memory` vector search is required. Do not delete it
  and do not fall back to the mixed broad Top-K, where precise/evidence vectors
  can crowd out Event memory.
- `PreciseMemorySemanticText` is required so semantic retrieval can understand
  the subject, counterpart, and meaning rather than using only an evidence
  excerpt.
- Current-turn materialization fences, removal of raw-chat memory fallback,
  optional lorebook reference delivery, and separate Edit Check memory-class
  panes are required.

### Confirmed current 4.0 defect

The dedicated aggregate-memory search has split ownership:

- `prepareTurnVectorShadow` writes `memory_search_result` and
  `memory_search_results`;
- `prepareTurnHydrateVectorMemoryHits` gates hydration with the broad
  `search_result` but consumes `memory_search_results`;
- `prepareTurnVectorRetrievalMethodStatus` also describes aggregate retrieval
  from broad status fields.

This can deterministically lose an aggregate Event hit when the broad and
memory searches have different outcomes. The second search is not the defect.
The defect is mixing the status of one search with the results of another.

If the user authorizes this repair, change the existing aggregate-memory owner
to consume its own status, error, count, and results. Do not add a fallback,
third search, extra guard, retry path, or compatibility branch.

### Source changes that remain unproven

- Current interaction admission and typed projection removed several 3.9.11
  review/source-binding checks. This may improve delivery or may over-promote an
  uncertain observation to current truth. It is not proven to cause the missing
  Event memory and is not authorized for change by this audit.
- Current structured-memory rendering no longer emits unknown raw JSON when no
  understandable summary can be formed. Restoring raw JSON is not an approved
  fallback. Any missing supported event must first be traced through the
  aggregate-memory owner.
- A live package showing one combined Long-term Memory box does not match the
  latest source, which renders `memoryDeliveryPlan.classes` separately. Package
  identity and loaded RisuAI behavior remain separate verification gates.

### Separate inherited defect

`stageFailedMemoryAdmissionResult` writes
`derived_admission_state='staged'`, while the canonical schema permits only
`pending` and `committed`. This contradiction exists in 3.9.11 as well as the
current source and matches the observed `chk_memory_source_admission` failure.

It is real, but it is not a 4.0 recall-policy difference. Do not use it as a
reason to redesign recall, precise memory, public projection, or lorebook
behavior. It requires a separately authorized, bounded lifecycle repair.

## Prohibited Work

The following are prohibited unless the user explicitly changes this contract:

- adding a guard, fallback, cache, watcher, retry path, compatibility branch,
  API, table, state field, or parallel retrieval path to cover an existing
  owner's wrong result;
- making exact evidence, `committed`, `source_observed`, `public`, or a separate
  public-support assertion a combined prerequisite for general semantic memory
  creation or aggregate recall;
- deleting an entire turn, summary, evidence set, or memory row because one
  nested item is private, uncertain, malformed, or incomplete;
- restoring raw-chat fallback or using selected-but-undelivered material as
  proof that another memory should be suppressed;
- hard-coding the user's story text, character names, model names, provider
  labels, prompt prose, scores, counts, or expected rankings into runtime
  classification or regression logic;
- fixing a test by copying the production policy into a test-only helper or by
  changing the fixture solely to make the current output pass;
- broad rollback to 3.9.11 that removes the verified 4.0 features listed above;
- expanding an authorized repair into Publisher, UI, schema, lifecycle,
  lorebook, or another memory lane merely because a neighboring issue is found.

Prefer deleting or correcting the wrong reference or condition in its existing
owner. Do not append another condition around it.

### Function-level changes

- `prepareTurnHydrateVectorMemoryHits`: replace the broad `search_result` gate
  and reason source with `memory_search_result`. This deletes the cross-owner
  decision; it does not add another condition.
- `prepareTurnVectorSearchAttempted`: read `memory_search_attempted`, because
  this trace describes the aggregate-memory selection attempt.
- `prepareTurnVectorRetrievalMethodStatus`: read
  `memory_search_result`, `memory_search_result_count`,
  `memory_source_revision_filter`, and the existing aggregate-memory result
  reader. It no longer reports broad typed-support status as Event-memory
  status.

Production code is six one-for-one key substitutions: `+6/-6`, net zero. A
safe line deletion was not available without changing another verified owner,
so the proposal does not force an artificial net reduction.
