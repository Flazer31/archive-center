## 0. 결정

4.0은 기억 개수를 무조건 늘리는 버전이 아니다. 현재 질문에 필요한 사건·발언·상태·관계·
주관 기억을 source·time·entity·knower·branch·revision과 함께 찾고, 사용자-facing 핵심
기억 K와 별도 지원 lane을 정확한 예산 안에서 최종 payload로 조립하는 버전이다.

3.7-F의 `core_objective_memory_delivery.v1` 의미와 UI를 다시 만들지 않는다.

- vector `topK`는 후보 검색 상한이다.
- `core_objective_memory_max_items`는 최종 핵심 객관 기억 K다.
- K가 10이고 적격 기억·예산이 충분하면 관련 핵심 기억 10개를 전달한다.
- 적격 기억이 부족하면 무관한 item으로 채우지 않고 coverage gap을 표시한다.

4.0은 3.9 기본 Publisher를 다시 구현하지 않는다. recall 결과와 delivery lineage를
Publisher와 본문 모델이 공유할 수 있게 하되 response-shaping authority는 3.9 계약을
그대로 따른다.

## 1. 소유권과 비범위

- Go는 query requirement, hard filter, retrieval fanout, hydration, dedupe, coverage,
  selection, compression, budget과 최종 block assembly를 소유한다.
- MariaDB는 canonical source·memory authority이고 Chroma는 재구축 가능한 후보 index다.
- JavaScript는 RisuAI observation과 Go가 만든 injection plan의 실제 payload 적용만 담당한다.
- similarity, graph edge, selected/delivered/co-fired/response-similar 상태는 truth,
  importance, merge, relation, closure와 canonical write 권한이 아니다.
- 4.0은 전체 관계 graph UI, semantic merge 자동화, 캐릭터 simulation, Publisher 다층 호출과
  원작 DB 독립화를 구현하지 않는다.

## 2. Query requirement

Go는 current input과 accepted state에서 질문별 requirement를 만든다.

- 사건·원인·결과;
- 특정 발언·약속·물건·장소·날짜;
- 현재와 과거 상태;
- 인물별 known/suspected/misinformed/hidden;
- 특정 상대와 domain의 관계;
- 습관·profile·말투 근거;
- unresolved thread와 이미 실현된 outcome;
- 현재 장면 continuity와 explicit reentry;
- 원작·Host Context·로어북 reference가 필요한 차원.

짧은 입력, 의미 없는 입력과 재개 요청도 무조건 넓은 최근 기록을 넣지 않는다. current
input에 명시 신호가 부족하면 직전 accepted scene, 현재 인물·상태와 open obligation 안에서
bounded continuity query를 만들고 부족함을 추적한다.

## 3. 검색 파이프라인

```text
current request requirement
  -> MariaDB hard filter
  -> exact ID·source·quote·date lookup
  -> lexical/full-text
  -> vector candidate
  -> source-backed relation·thread neighborhood
  -> Go hydration
  -> lifecycle·privacy·knower·authority validation
  -> semantic/source dedupe
  -> coverage-aware selection
  -> memory_injection_plan.v2
```

### 3.1 Hard filter

후보 검색 전에 다음이 current scope와 일치해야 한다.

- session과 Host chat binding;
- branch, logical/source turn, generation과 revision;
- active-final/source acceptance와 tombstone/superseded 상태;
- entity와 speaker identity;
- story time, scene scope와 validity interval;
- knower·visibility·privacy·reveal ceiling;
- objective/belief/proposal/uncertain authority;
- source hash와 dependency generation.

필수 좌표가 unknown이면 더 넓은 후보로 완화하지 않고 해당 dimension을
`unavailable/degraded`로 보고한다.

### 3.2 검색 lane

1. exact source/ID/quote/date/entity;
2. lexical/full-text;
3. vector semantic 후보;
4. 기존 source-backed relation·thread edge의 bounded neighborhood;
5. hierarchy zoom;
6. 선택적으로 승인된 reference provider.

embedding 또는 Chroma가 없어도 exact·lexical·recent accepted continuity는 작동해야 한다.
vector/graph 장애는 후보 폭만 줄이고 truth·privacy·K·예산을 넓히지 않는다.

### 3.3 중복

동일 source occurrence, 동일 atomic meaning과 한 항목의 raw/summary/derived 표현은 의미
중복으로 합치되 source provenance를 잃지 않는다. 서로 다른 인물·knower·time·branch의
유사 문장을 같은 사실로 병합하지 않는다.

## 4. `memory_recall_plan.v2`

plan은 최소한 다음을 구분한다.

- requirement와 query seed;
- eligible·selected·deferred·excluded item;
- source/ref, memory kind와 delivery class;
- entity·time·knower·visibility·authority·lifecycle;
- retrieval lane과 score가 아닌 selection reason;
- dedupe group과 retained source refs;
- coverage dimension과 gap reason;
- requested K, eligible K, selected K와 delivered K;
- lane별 문자·item 예산;
- degraded dependency와 fallback owner;
- plan ID/hash, request/branch/generation/revision fence.

selected는 delivered가 아니다. 최종 compaction·예산·payload 적용 뒤 실제 delivered item과
hash를 다시 확정한다.

## 5. `memory_injection_plan.v2`

최종 plan은 다음 ordered lane을 독립적으로 조립한다.

1. current input obligation;
2. 핵심 객관 기억 K;
3. 직전 continuity;
4. direct evidence;
5. time/state;
6. subjective/perspective;
7. relationship/habit/profile;
8. hierarchy zoom;
9. world/reference;
10. protected secret·agency·must-not guard;
11. Publisher가 실제 사용한 `guidance_support`;
12. output guidance.

동일 text와 source ref를 여러 lane에서 반복하지 않는다. support-only item은 핵심 객관 기억
K를 소비하지 않지만 source·privacy·lifecycle·중복·문자 예산에서는 면제되지 않는다.

item 중간 절단으로 의미·부정·주체·시점이 바뀌는 경우 전체 item을 defer한다. Go는 최종
text·order·hash·예산·defer reason을 반환하고 JavaScript가 이를 다시 계산하지 않는다.

## 6. 1.0 체감과 Publisher 연결

4.0은 다음 전달 형태를 보장하는 방향으로 3.9 Publisher를 강화한다.

- 짧고 직접 관련된 핵심 기억 K;
- 이전 기억과 현재 continuity의 분리;
- 주관 기억·관계·profile·세계 자료의 별도 lane;
- 본문에는 짧은 기억, Publisher에는 bounded eligible support;
- Publisher가 사용한 support ref의 본문 전달 가능성 증명;
- 기억 내용을 인용하라고 강제하지 않고 행동·subtext·장면 반응으로 표현.

recall이 성공했다는 사실만으로 Publisher가 장면을 전진시키거나 관계·closure를 만들 수
없다. `none`에서는 recall과 factual support는 유지하지만 Publisher plan은 0이다.

## 7. 선택 후보 — RisuAI 로어북 read-only 색인

상태: `candidate_requires_explicit_activation`

전체 RisuAI lorebook reader, native activation engine, DB/Chroma mirror와 decorator·확률·
scan depth 재구현은 계속 금지한다. 승인 시 4.0의 선택 packet으로 허용할 수 있는 범위는
다음뿐이다.

- 사용자 동의를 받은 entry별 read-only snapshot;
- character global, chat local, enabled module scope hard filter;
- exact/key/lexical 검색과 선택적 semantic 후보;
- entry/source/revision/hash·scope·lifecycle 보존;
- native activation이 노출되지 않으면 `activation_unknown`;
- 첫 단계 `search_only`: Explorer·trace만, prompt 전달 0;
- 후속 명시 opt-in `reference_assist`: 별도 예산의 source-linked reference;
- 핵심 기억 K, 원작 canonical, 관계·profile·session event로 자동 병합 0.

이 선택 packet을 활성화하면 4.1의 edit/delete/module disable/branch/reindex lifecycle
matrix가 함께 release blocker가 된다. 비활성 상태에서는 4.0 core 완료를 막지 않는다.

## 8. 구현 packet

| packet | 단일 책임 | 다음 packet을 막는 exit evidence |
|---|---|---|
| `4.0-A` | MariaDB authority·scope·branch·knower·time hard filter | wrong-session/branch/entity/knower/time/tombstone/superseded 후보 0 |
| `4.0-B` | exact·lexical·vector·relation/thread-neighborhood retrieval | 각 lane contribution·failure가 분리되고 vector/edge가 truth가 되지 않음 |
| `4.0-C` | requirement·coverage-aware `memory_recall_plan.v2` | 고정 top-k 채우기 없이 selected/deferred/gap reason과 K count 재현 |
| `4.0-D` | semantic/source dedupe와 hierarchy zoom | 다른 entity/time/knower 사실 오병합 0, raw/summary 반복 0 |
| `4.0-E` | `memory_injection_plan.v2`·독립 예산·Go final assembly | item text/order/hash와 실제 payload 일치, JS 정책 계산 0 |
| `4.0-F` | provider/Chroma 장애·기존 DB·장기 session 성능 gate | exact fallback·main 응답 보호, degraded 상태·latency·cost 증거 |
| `4.0-G` | 선택형 lorebook `search_only`→`reference_assist` | 명시 승인·scope·lifecycle·native activation unknown·별도 예산 gate |

## 9. 필수 회귀

- K=0/1/10, 적격 부족·충분, 문자 예산 부족·충분 조합;
- exact 발언·날짜·약속·물건·장소 회수;
- 같은 이름의 다른 인물과 공유 별칭 교차 주입 0;
- wrong knower·secret·reveal ceiling 누출 0;
- current/history·flashback/planned/hypothetical 혼합 0;
- tombstone·superseded·wrong branch·stale generation item 0;
- vector 제거 시 exact·lexical 정상, gap 정직 표시;
- graph signal 제거·반전 시 selection fixture 실패;
- semantic dedupe 뒤 source provenance 보존;
- selected와 delivered count·hash 불일치 0;
- 핵심 K 때문에 protected/direct/state lane 누락 0;
- support lane 때문에 핵심 K 감소 0;
- Publisher 사용 ref가 payload에 없을 때 해당 guidance 적용 0;
- lorebook 비활성에서 catalog read·index·prompt 전달 0;
- lorebook `search_only`에서 prompt 전달 0;
- 실제 payload와 HUD/explorer item lineage 일치.

## 10. 출시 중단 조건

- vector `topK`를 사용자-facing 최종 K로 다시 해석;
- 무관한 item으로 K를 채움;
- selected·similarity·graph edge를 truth·importance·relation로 승격;
- privacy·lifecycle filter 장애가 더 넓은 후보로 fail-open;
- main memory와 support/reference budget을 합쳐 한 lane이 다른 lane을 침범;
- Publisher·Critic·reference raw text를 memory evidence로 저장;
- JavaScript가 ranking·selection·dedupe·budget·block order를 계산;
- lorebook native activation을 추측하거나 RisuAI 발동 엔진을 복제;
- actual RisuAI payload 증거 없이 `release_gate_verified` 선언.

## 11. 다음 버전으로의 인계

4.0은 4.1에 plan/item dependency, source revision, index generation, selected/delivered hash와
defer/gap lineage를 전달한다. 4.1은 edit/delete/reroll/branch/rebuild 뒤 이 결과가 stale로
부활하지 않음을 보장한다.

4.6~5.0은 4.0 recall 결과를 read-only로 소비한다. 별도 ranking, 임시 graph truth와 두 번째
injection planner를 만들지 않는다.
