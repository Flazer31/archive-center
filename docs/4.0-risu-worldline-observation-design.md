# Archive Center 4.0 RisuAI Worldline Observation Design

Status: `bounded_worldline_topology_canvas_implemented_live_unverified`
Runtime scope: branch observation, existing session routing, parent/child
completed-turn ownership for automatic active-chat backfill, lineage persistence,
and bounded Timeline topology-canvas presentation
Recorded: 2026-08-18
Scope: RisuAI branch observation, Archive Center session/worldline identity,
fork lineage, and a deferred retrieval-isolation boundary

## 1. Goal

Detect a RisuAI chat branch without inventing a second JavaScript policy engine.
Use the strongest Host observation that RisuAI exposes, and let the existing Go
backend decide the Archive Center session, logical turn, worldline lineage, and
persistence consequences.

The product result is:

- a RisuAI branch receives a distinct Archive Center session/worldline;
- copied history before the fork remains attributable to the parent;
- child history after the fork does not mutate or leak into the parent;
- reroll remains a replacement inside one logical turn, not a new worldline;
- output-listener branch observation does not change the existing
  `active_final` owner;
- missing or conflicting Host evidence remains unresolved instead of being
  guessed from prompt text, message count, or content similarity.

This is not a request to add another watcher, polling loop, branch database, or
parallel finality path.

### 2.2 Official branch shape

At the inspected commit, RisuAI's branch action:

1. snapshots the current chat;
2. creates a new `chat.id`;
3. retains messages through the selected fork message;
4. appends a disabled comment containing `branchedfrom`, the parent `chat.id`,
   and the source message `chatId`;
5. inserts the child chat and makes it active.

Official source:

- <https://github.com/kwaroran/Risuai/blob/22ea4a64b7a2178ca10957dc53f14a0404e31587/src/lib/ChatScreens/Chat.svelte>

Important boundary: the inspected source commit is parser-shape evidence, not
an observed loaded-Host commit. The loaded RisuAI version/commit remains
unknown unless the Host exposes it at runtime. The public plugin type does not expose a typed
`branchCreated(parent, child, forkPoint)` event or a typed `branchId`. The
`branchedfrom` comment is a supported-version Host shape found in official
source, not a general cross-version plugin contract.

Therefore:

- `chat.id` is forwarded as an opaque observed Host chat identity;
- Archive Center must not rename it to an official RisuAI `branch_id`;
- the exact `branchedfrom` shape is identified by the versioned parser contract
  `risu_branchedfrom.v1`, listener capability, and the exact marker structure;
- if the shape is absent or changed, the result is `not_exposed` or
  `lineage_unresolved`, not a text/content-based guess.

### 2.3 Official reroll shape is different

RisuAI reroll operates on the active chat and generation/swipe state. It does
not create the new child `chat.id` used by the branch action.

Official source:

- <https://github.com/kwaroran/Risuai/blob/22ea4a64b7a2178ca10957dc53f14a0404e31587/src/lib/ChatScreens/DefaultChatScreen.svelte>

Archive Center must consequently distinguish:

- same Host chat + same user anchor + new generation/swipe: logical-turn
  replacement;
- new Host chat + validated branch provenance: child worldline;
- new Host chat without validated provenance: new independent session with
  unresolved lineage.

## 4. Authority Model

There are two evidence classes, but only one Go decision owner.

### 4.1 Host evidence

JavaScript may report only observed facts:

- the output listener fired, or the same raw active-chat branch facts were read
  immediately before an automatic historical backfill sweep;
- active `characterIndex`, `chatIndex`, and `messageIndex`;
- opaque child `chat.id`;
- the last/highest-index disabled `branchedfrom` marker and its immediately
  preceding source-message identity, role, and disabled state;
- when that source is `char`, the nearest preceding enabled user's opaque
  message ID as the existing logical-turn anchor. At most three message facts
  are sent; a `user` source is its own anchor and needs only two.

JavaScript does not decide `is_branch`, parent session, fork turn, inherited
memory range, or deletion range.

### 4.2 Backend assessment

Go decides:

- Archive Center session binding for the observed Host chat;
- whether the observation is a reroll, edit, independent chat, or branch;
- parent Archive Center session;
- fork source message and canonical fork turn;
- lineage state;
- active/superseded/deleted source revisions;
- later retrieval and invalidation scope.

The backend assessment must be categorical, not a confidence score:

| State | Meaning |
| --- | --- |
| `confirmed` | Exact marker/source coordinates resolve to one active parent source revision |
| `unresolved` | Host chat is distinct, but parent or fork point is not exposed/provable |
| `conflict` | Host provenance contradicts the observed chat prefix or stored routing |
| `not_applicable` | Ordinary chat, reroll, or edit inside the same Host chat |

`unresolved` and `conflict` never silently import parent memory or merge child
state into a parent.

## 5. Single Decision Flow

### Phase A: request observation

`beforeRequest` continues to report the active Host chat identity and current
message coordinates. Before an automatic full active-chat backfill sweep, the
thin adapter also reads the raw active-chat message array before disabled
markers are filtered. If the supported branch marker is present, it sends the
same bounded marker/source/user-anchor facts through the existing session
routing request and waits for the Go assessment. This observation is labeled
`active_chat_pre_backfill`, never falsely labeled as `output`. No marker means
no additional worldline request and preserves ordinary cold-start recovery.

### Phase B: output-listener branch observation

The official output listener freezes the callback object synchronously. If no
disabled `branchedfrom` candidate exists, it sends no extra request. Otherwise
it forwards only the last marker and its immediate predecessor to the existing
session-routing request. For a `char` source it also forwards the nearest
preceding enabled user anchor, then returns without waiting for backend latency.

### Phase C: Go lineage resolution

For a new Host chat:

1. resolve the child Archive Center session through the existing session-route
   owner;
2. validate that the supported `branchedfrom` record names an existing parent
   Host chat and source message;
3. resolve that parent Host chat through existing route bindings;
4. require that the immediately preceding child message identity equals the
   marker source identity;
5. use a `user` source as its own anchor; for a `char` source require the one
   additional preceding enabled user anchor observation;
6. derive the existing durable logical-turn ID from the exact parent Host chat
   ID and opaque user anchor ID, then require one active revision with that ID;
7. use that unique revision's canonical turn index;
8. emit `confirmed`, `unresolved`, or `conflict`;
9. persist every non-absent observed assessment through the existing lineage
   owner; store only a bounded reason code for unresolved/conflict states.

The confirmed row also stores the validated fork source role. Go derives the
completed-turn ownership boundary without persisting a duplicate cutoff:

- `char` source: the parent owns through `fork_turn`;
- `user` source: the parent owns through `max(0, fork_turn - 1)` because the
  child response may complete that same logical turn.

This role-specific validation reuses the existing source-revision and
logical-turn owners. It does not infer from content or indexes and adds no user
message storage field.

A starter/greeting branch with no accepted active source revision remains
`unresolved`. It stores no proven parent session or fork turn and therefore
renders no fork badge; no parent import is inferred.

Do not use fuzzy text similarity, prompt prose, character names, total message
count, or a content hash by itself to choose the parent.

### Phase D: automatic historical backfill ownership

Only `automatic_active_chat_full_sweep` pair routing consumes this boundary.
Pairs at or before the parent-owned boundary stop in the existing routing
owner before `/complete-turn`, Critic, or memory persistence. Pairs after the
boundary keep their original child-local turn. Existing copy/migrate/attach
baselines remain the first owner when present. Missing, legacy, invalid, or
conflicting lineage fails the automatic sweep closed. Accepted-final transport
recovery, next-host recovery, and explicit recent rebuild are unchanged.

### Phase E: source acceptance boundary

This slice does not change source acceptance. The existing `afterRequest` and
later Host-observation machinery remain the finality owner until a separate
displayed-final contract is source- and live-proven.

### Phase F: retrieval and invalidation

This phase is not authorized until lineage detection is source- and
live-verified.

The intended rule is:

- parent history through the confirmed fork point may be inherited;
- parent history after the fork is ineligible in the child;
- child history is ineligible in the parent and sibling branches;
- deletion/reroll in one child invalidates only that child after its affected
  turn;
- common pre-fork history is not physically duplicated unless the existing
  storage owner requires and proves that behavior.

## 6. Existing Storage Reuse Decision

No new table is approved.

`session_fork_lineage` is the first reuse candidate because it already stores:

- child session/scope;
- parent/copied-from session/scope;
- divergence marker;
- provenance source;
- inheritance mode;
- inherited item references.

The existing owner is extended in place with a versioned state, canonical fork
turn/source identity, validated source role, and a nullable automatic
idempotency key. Manual rows
keep a null key. Automatic keys are coordinate-based and unique within the
child session, so a direct session migration preserves both the key and future
upsert identity. `unresolved` may promote to `confirmed`; a confirmed automatic
record is immutable and remains visible after the Host marker or parent source
is later removed. No parent Archive Center session is stored until its route is
proved by read-only resolution.

## 7. No Parallel Finality Growth

The output listener is a branch/worldline observer only. It does not emit a
source-acceptance contract, queue a turn, retry persistence, or act as a
fallback for finality. There is no DOM text, delayed timer, message-content, or
chat-name heuristic for branch lineage. An unavailable listener leaves
automatic branch observation unavailable; explicit operator repair remains a
separate existing path.

## 8. Approved Timeline UI Contract

The implemented Timeline canvas source/test surface is compact/small-window
first:

- the Timeline has no permanent session/worldline or detail sidebar;
- a compact selector and action toolbar preserve session selection,
  attach/copy/migrate/delete, rollback/cleanup, reload, and load-more actions;
- Go returns the bounded family topology, confirmed edges, active ancestor
  path, deterministic logical layout, and typed `ready|partial|unavailable`
  state through the existing presentation ViewModel;
- JavaScript projects that supplied layout onto a 2D canvas and owns only
  viewport interaction: one-pointer pan, pointer-centered wheel zoom,
  two-pointer pinch, tap selection, double-tap focus, current recenter, and
  fit-all;
- selecting a node reuses the existing Timeline/detail/edit flows and does not
  switch the RisuAI Host chat;
- turn history and detail/edit surfaces remain available in responsive drawers;
- deleting a parent Timeline turn does not delete the child's copied history.

This canvas is lineage topology only. It does not claim parent-memory
inheritance, sibling/post-fork retrieval isolation, Host branch switching, or
semantic episode/chapter/turn zoom. Those remain deferred until their Go-owned
data contracts exist. The family read is bounded and exposes truncation rather
than inventing missing parents or edges.

## 9. Implemented and Deferred Slices

This bounded slice implements only:

- official output-listener registration/removal and a non-blocking, branch-only
  observation callback;
- bounded raw active-chat branch observation before automatic historical
  backfill, using the same routing endpoint and parser contract;
- the existing session-routing request as the sole transport/decision entry;
- read-only parent route and active-source validation in Go;
- idempotent state persistence on `session_fork_lineage`;
- Go-owned `user|char` completed-turn ownership for automatic full sweeps only;
- one shared Go worldline ViewModel for route and scalar Timeline status;
- one bounded Go-owned topology ViewModel on the existing presentation route,
  with confirmed-edge, conflict/cycle, active-path, and truncation handling;
- a responsive Timeline canvas that renders only those supplied nodes, edges,
  and logical coordinates while retaining existing Timeline operations.

Displayed-final/source acceptance replacement is deferred because the official
output callback occurs too early to prove it. Lineage-aware retrieval and
invalidation are also deferred. After live lineage proof, that later work may:

- allow common parent history only through the fork boundary;
- isolate parent-post-fork, child, and sibling memories;
- bind reroll/delete/reindex invalidation to the active worldline.

Expected result:

- child recalls common history and its own continuation;
- parent and siblings receive zero child-private/post-fork material;
- no physical duplication resurrects stale memory after deletion or reroll;
- current 4.0 memory/lorebook budgets and selection are unchanged except for
  worldline eligibility.

## 10. Regression Matrix

| Scenario | Required result |
| --- | --- |
| ordinary new turn | no extra worldline routing request and no lineage row |
| reroll | same worldline and logical turn; prior final superseded |
| byte-identical reroll | new observed revision may replace prior final without creating a branch |
| edit | same worldline; replacement classification remains distinct from branch |
| branch at turn N | new child session; confirmed parent and fork point N |
| branch before new output | bounded pre-backfill observation; inherited parent pairs do not enter the child DB |
| branch from `char` at turn N | parent owns through N; child starts at N+1 |
| branch from `user` at turn N | parent owns through N-1; child response may complete N |
| child first output | listener reports branch facts only; source finality is unchanged |
| independent copied/imported chat | unresolved/independent unless official branch provenance validates |
| malformed branch marker | conflict; no automatic inheritance |
| starter/greeting with no active source | unresolved; no parent import or fork badge |
| missing listener capability | explicit unavailable; no timer/DOM/content fallback |
| delete in child | parent/sibling histories remain intact |
| reroll in child | only child active final and descendants are replaced |
| restart | session route, lineage, active final, and fork boundary remain identical |

Tests must use content-neutral synthetic IDs and messages. They must not
hard-code the user's RP text, character names, plugin names, model names,
provider labels, or expected policy scores.

## 11. Release Evidence Gate

Source and mock tests do not prove loaded behavior. Live verification of this
bounded slice requires separate evidence for:

1. official upstream source and supported RisuAI version;
2. Archive Center source tests;
3. built package hashes and version identity;
4. loaded RisuAI listener callbacks;
5. real MariaDB route, source revision, and lineage rows;
6. reroll, delete, branch, descendant branch, and restart scenarios.

Real Chroma retrieval isolation, visible final payload lineage, sibling
eligibility, and reindex behavior belong to the deferred retrieval slice, not
to this implementation claim.

Do not call Publisher success, memory selection success, or a green fixture
proof of worldline completion.
