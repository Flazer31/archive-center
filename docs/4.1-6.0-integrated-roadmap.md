# Archive Center 4.1~6.0 통합 로드맵

상태: `canonical_planning_index`

기준일: 2026-08-24

범위: Archive Center 4.1의 기억 탐색부터 6.0 Living World까지의 버전 소유권,
확장형 플러그인 연동, 단계별 산출물과 선행 관계

## 0. 문서 지위

이 문서는 Archive Center 4.1~6.0의 **현재 단일 계획 정본**이다. 같은 범위를 다루는
기존 통합·상세·검토 문서는 설계 근거와 역사적 결정 기록으로 보존하지만, 계획 문서
사이의 버전 번호, 제품 이름과 계획 단계 소유권이 충돌하면 이 문서를 우선한다. 현재
구현 상태는 production source, 회귀, package, loaded/live 증거를 각각 확인하며 이 계획
문서가 그 증거를 덮어쓰지 않는다.

특히 다음 혼선을 정리한다.

- 과거 `3.6-4.1` 문서의 lifecycle·복구용 `4.1-A~G` 번호는 현재 4.1이 아니다. 그
  범위는 4.0에 흡수되었고, 현재 4.1은 기억 Locator·계층 탐색이다.
- 4.1과 4.2는 계획 내용과 버전 후보 배정을 통합하되 기존 승인 상태를 임의로 올리지
  않는다. 두 버전은 `VERSION_ASSIGNMENT_CANDIDATE`이며 구현 승인은 별도다.
- 4.3~4.5는 Archive Center 내부 기능만의 연속이 아니라, 별도로 설치되는 확장형
  플러그인과의 연동 구간이다.
- 확장형 플러그인의 현재 제품 이름은 `AC Ensemble Agent`다. `Risu Recomposer`,
  `AC Recomposer Agent`와 2.5 계보는 현재 제품 이름으로 되살리지 않는다.
- 현재 source의 `archive_center.recomposer_enhancement.v1`과
  `archive_center.recomposer_bridge.v1`은 이미 존재하는 과도기 계약 이름이다. 새 제품
  이름을 뜻하지 않는다. 향후 replacement/removal이 승인될 때에만 명시적인 versioned
  migration과 제거 조건을 먼저 정하며, 호환성을 깨는 무음 rename을 하지 않는다.
- 4.6~5.0은 버전 배정이 확정된 구현 전 계획이다.
- 5.1~5.9는 Living World 구축·통합 단계이고, 6.0은 검증된 profile만 제품 경계로
  승격하는 milestone이다.

문서에 계획이 적혀 있다는 사실은 source 구현, package 반영, 실제 RisuAI 로드,
MariaDB·Chroma 작동 또는 장기 RP 품질 증거가 아니다.

## 1. 판정 용어

| 용어 | 의미 |
|---|---|
| `VERIFIED_SOURCE` | 현재 production source에서 실제 owner와 호출 경로를 확인함 |
| `REGRESSION_ONLY` | production 경로를 대상으로 한 자동 회귀가 있으나 live 증거는 아님 |
| `IMPLEMENTED_UNVERIFIED` | source 구현은 있으나 실제 RisuAI 또는 실 DB 검증이 남음 |
| `VERSION_ASSIGNMENT_CANDIDATE` | 기능과 후보 버전은 정했지만 구현 승인과 release blocker 여부는 별도임 |
| `VERSION_ASSIGNED_PLAN` | 버전과 책임은 정했지만 해당 버전 구현 완료를 주장하지 않음 |
| `DRAFT_VERSION_PLAN` | 상세 설계가 있으나 구현 전 owner mapping과 계약 확정이 더 필요함 |
| `LIVE_VERIFIED` | 실제 지원 RisuAI·DB·provider·표시 최종본 계보로 확인함 |
| `HISTORICAL` | 결정 근거로 보존하지만 현재 버전·제품 정본은 아님 |
| `OBSOLETE` | 현재 제품 경로로 되살리지 않는 폐기된 이름·구조·소유권 |

`selected`, `rendered`, `delivered`, `stored final`과 `displayed final`은 서로 다른
상태다. 사용자가 실제로 본 출력의 RP 효과나 기억 저장을 주장하려면 displayed-final
lineage와 complete-turn admission을 별도로 확인해야 한다.

## 2. 전체 제품 흐름

```text
4.0 memory, source, branch, lifecycle baseline
  -> 4.1 source locator and hierarchy explorer
  -> 4.2 reviewed cleanup, quarantine and undo
  -> 4.3 role-specific story context and subjective memory packets
  -> 4.4 AC Ensemble Agent integrated preprocessor cutover
  -> 4.5 AC Ensemble Agent ensemble performance and displayed-final lineage
  -> 4.6 source-linked entity/relation graph and execution foundation
  -> 4.7 character/relationship execution cards
  -> 4.8 world/faction/thread execution slices
  -> 4.9 model-capability-adaptive Publisher
  -> 5.0 output-fidelity correlation and product evidence
  -> 5.1 deterministic world-state transition kernel
  -> 5.2 actor intent, value vector and scheduler
  -> 5.3 Living World typed action/outcome extension of the Ensemble path
  -> 5.4 offscreen hypothesis simulation
  -> 5.5 realization receipt and admission extension
  -> 5.6 advanced conflict and causality resolver
  -> 5.7 long-horizon character dynamics
  -> 5.8 adaptive orchestration and optional review
  -> 5.9 Living World release candidate
  -> 6.0 Archive Center Living World
```

4.3~4.5와 5.3은 중복 단계가 아니다. 4.3~4.5는 역할별 자료, 정확히 하나인
전·후처리 경로와 표시 최종본 계보를 완성한다. 5.3은 5.1~5.2의 typed action과
successor/outcome을 그 동일한 Ensemble 경로에 연결한다.

| 버전군 | 현재 계획 상태 |
|---|---|
| 4.1~4.2 | `VERSION_ASSIGNMENT_CANDIDATE` |
| 4.3~5.0 | `VERSION_ASSIGNED_PLAN` |
| 5.1~6.0 | `DRAFT_VERSION_PLAN` — 6.0의 기능 성격은 profile-promotion milestone |

위 화살표는 제품 설명 순서다. 후보 배정인 4.1·4.2의 구현 완료가 4.3의 무조건적인
선행 gate라는 뜻은 아니며, 실제 필수 선행은 7절의 표를 따른다.

## 3. 영구 소유권과 금지선

### 3.1 Archive Center Go

Archive Center Go는 다음을 소유한다.

- canonical source, 기억, 관계, 상태, thread와 revision;
- session·branch·request·generation·message fence;
- 기억 검색·선택·예산·privacy·authority와 역할별 할당;
- 활성 역할 선정, 공개/비공개 context 범위와 실행 순서;
- 상태 전이 validation, stop reason, admission과 rollback;
- ViewModel, 안정 오류 코드와 실행 trace;
- 실제 displayed final을 소비하는 Critic·memory·complete-turn 결정.

### 3.2 Archive Center.js

Archive Center.js는 공식 RisuAI Host 관찰, backend transport, backend plan의 실제
payload 적용, 최종 표시 관찰, DOM·설정 UI와 최소 transient state만 소유한다. 기억
재선택, 역할 편성, budget, 상황극 순서, canonical 결과 또는 fallback 정책을 계산하지
않는다.

### 3.3 AC Ensemble Agent

AC Ensemble Agent는 Archive Center와 별도로 설치 가능한 확장형 플러그인이다. 현재
standalone source는 자체 전처리 감독관, 전문 작성자, 선택적 품질 비평가와 최종 작곡가로
한 장면을 재작성하는 경로를 구현했지만 실제 RisuAI live 검증 전이다.

향후 integrated mode가 구현되면 다음 경계를 따른다.

- Archive Center Go가 승인한 역할, 공개 장면 상태와 역할별 private context만 사용해
  감독관·나레이터·Actor의 `ensemble_performance`를 실행한다.
- 역할 AI의 문장·합의·점수는 canonical truth가 아니다.
- 다른 Actor의 private memory 원문을 전달하지 않는다.
- integrated 실패를 standalone mode로 자동 전환하거나 두 mode를 한 요청에서 함께
  실행하지 않는다.
- 최종문을 반환할 수 있지만 canonical admission은 Archive Center Go가 실제 표시와
  revision을 확인한 뒤 결정한다.

승인된 계획대로 역할별 model·endpoint·추론 강도·호출 여부와 이에 필요한 provider
credential 설정은 별도 플러그인이 소유하고 Archive Center는 이를 복제하지 않는다.
integrated orchestration과 credential을 실제 호출에 결속하는 transport 경계는 구현 전
contract packet에서 확정한다. AC Ensemble standalone의 나머지 plugin-local 상태를
Archive Center integrated mode의 영구 소유권으로 자동 승격하지 않는다.

### 3.4 공통 금지선

- 두 번째 canonical memory, graph 또는 world-state 저장소 추가;
- JavaScript의 기억·관계·상태·예산·순서 정책 계산;
- 플러그인 이름, prompt 문구, 작품·장르·모델명 allowlist로 route 판정;
- 여러 모델의 합의·confidence·문장을 truth 권한으로 승격;
- 전체 raw chat 또는 모든 private memory를 역할 수만큼 복제;
- 실패 시 stale plan, last-good guidance 또는 다른 mode를 숨겨서 재사용;
- 하나의 항목 누락을 이유로 유효한 전체 결과를 폐기;
- 비용 절감이나 안전을 이유로 세계·인물을 무조건 정지;
- 표시되지 않은 main draft나 중간 role turn을 Critic·memory에 저장.

## 4. 현재 출발점

| 항목 | 현재 판정 | 4.1~6.0에서의 의미 |
|---|---|---|
| Archive Center 4.0.0 memory·Publisher 기반 | `VERIFIED_SOURCE`, 별도 live 범위 존재 | 모든 후속 버전이 소비하는 canonical owner |
| Archive Center 4.0.0 branch·worldline 기반 | `INFERRED`, partial | persistent fork-lineage·관련 route는 있으나 공식 RisuAI branch와 연결된 완성 제품 흐름은 미검증 |
| `archive_center.recomposer_enhancement.v1` | `VERIFIED_SOURCE` | 선택된 Archive 정보를 확장 플러그인에 주는 read-only 과도기 기반 |
| `archive_center.recomposer_bridge.v1` | `VERIFIED_SOURCE` | Archive Center.js가 게시하는 transient one-way bridge |
| source의 `AC Recomposer Agent.js` | `VERIFIED_SOURCE` | 현재도 수동 설치 가능한 `archive_center.recomposer_bridge.v1` consumer이지만 제품 정체성은 historical이며 신규 확장 제품 이름이 아님 |
| workbench의 `AC Ensemble Agent 0.6.2-beta.1` | `IMPLEMENTED_UNVERIFIED` standalone | 새로 작성한 독립 확장 제품. Recomposer의 후속 버전이 아니며 source repo·Archive package 자동 구성 요소도 아님 |
| AC Ensemble standalone 자동 회귀 | `REGRESSION_ONLY` 61/61 | update-reset 설정 보존과 standalone source의 회귀 증거 |
| AC Ensemble `standalone_complete` | 미달성 | 실제 RisuAI load·전처리·후처리·표시 검증 전 integrated 구현 진입 금지 |
| Archive Center↔Ensemble exactly-one preprocessor | `VERSION_ASSIGNED_PLAN` | 4.4 소유 |
| Ensemble final receipt→displayed-final-only admission | `VERSION_ASSIGNED_PLAN` | 4.5 소유 |

현재 v1 bridge가 존재한다는 사실을 4.3~4.5 완료로 해석하지 않는다. v1은 Archive
Center 선택 정보를 historical Recomposer consumer의 자체 ledger에 붙이는 단방향
optional enhancement다. current-request capability claim, transactional preprocessor
cutover, 역할별 provider privacy projection, final receipt와 displayed-final-only admission은
별도 계획 범위다.

현재 AC Ensemble Agent source에는 `archive_center`, `recomposer`, bridge 또는
`ensemble_packet` runtime consumer가 없다. 그러므로 Recomposer v1 bridge와 Ensemble을
현재 연결된 것으로 표현하지 않는다. Archive Center의 기존 단일 perspective helper도 한
resolved POV holder를 위한 현재 기능일 뿐, 4.3의 공통 story context·역할 roster·다중 Actor
assignment 구현 증거가 아니다.

Archive Center 관리형 package의 RisuAI plugin payload에는 `Archive Center.js`만 포함되며
Recomposer와 Ensemble을 복사·자동 설치·자동 로드하지 않는다. 두 확장 파일은 각각 별도
수동 설치형이고, AC Ensemble의 현재 정본 개발 경로는 active source repo 밖의
`workbench/ac-ensemble-agent`다.

## 5. 4.1~5.0 버전 계획

### 4.1 — 기억 Locator·계층 탐색

상태: `VERSION_ASSIGNMENT_CANDIDATE`

목적은 현재 질문·인물·사건·관계에서 시작해 어떤 기억이 어디에서 왔고 실제 요청에
어떻게 사용됐는지 사용자가 재현하도록 하는 것이다.

주요 범위:

- subject·claim·question·exact ref별 stable source pointer;
- found/not-found/degraded trace와 사용한 exact·lexical·vector·hierarchy lane;
- query·scope·session·branch·revision·knower·visibility·expiry reuse fence;
- turn→episode→chapter→arc 상향·하향 탐색;
- 인물·관계·사건→source와 시점 이동;
- selected→rendered→delivered lineage;
- excluded/deferred 이유와 부족한 좌표;
- current와 superseded/tombstoned history 비교;
- Go ViewModel과 source 이동 UI.

4.1은 not-found를 “사실이 없음”으로 저장하지 않고 canonical memory, ranking, K,
injection 또는 lifecycle을 새로 소유하지 않는다.

인계: stable source pointer, dependency lineage와 영향 범위를 4.2·4.3에 제공한다.

### 4.2 — 기억 정리·격리·검토·되돌리기

상태: `VERSION_ASSIGNMENT_CANDIDATE`

목적은 위험한 semantic mutation을 자동 실행하지 않고 사용자가 source와 영향 범위를
확인한 뒤 정리하도록 하는 것이다.

주요 범위:

- exact duplicate와 idempotent replay의 자동 no-op;
- cross-source·entity·time·knower·privacy merge proposal;
- keep/remove source와 영향받는 relation·summary·visibility·projection 표시;
- quarantine, review, revision mapping, rebuild lineage와 undo 범위;
- dependent undo가 불가능할 때 선행 undo와 영향 graph 보고;
- 변경 전·후 read model과 audit 결과.

낮은 조회수, 오래됨, activation 또는 단일 점수만으로 자동 prune하지 않는다. 4.0의
transaction·rollback을 대체하지 않고 그 owner를 통해 승인된 변경만 수행한다.

인계: review·undo가 끝난 source 상태와 audit 결과를 4.3 이후가 소비한다.

### 4.3 — 역할별 이야기 문맥·인물별 주관 기억

상태: `VERSION_ASSIGNED_PLAN`

4.3은 Archive Center와 AC Ensemble Agent 연동의 **Archive Center 자료 생산 단계**다.
확장 플러그인이 모든 기억을 똑같이 읽지 않도록 역할별 packet을 만든다.

주요 범위:

- RisuAI가 실제 제공한 캐릭터·페르소나·활성 로어북·작가 노트 관찰 lineage;
- arc·chapter·episode·scene·현재 thread를 사용한 공통 배경 이야기;
- 감독관용 장면 목표·갈등·제약·미해결 의무;
- 나레이터용 공개 세계·시간·장소·사건·서술 연속성;
- Actor별 경험·전언·추론·오해·감정 원인·목표·비밀;
- objective event와 subjective belief 분리;
- 역할 roster, 포함·제외 이유와 request fence;
- private memory의 cross-Actor 유출 차단;
- 전체 raw chat을 역할 수만큼 복제하지 않는 계층형 budget.

논리 산출물:

- 공통 story-context packet;
- Actor별 perspective packet;
- role roster와 source-assignment lineage;
- 4.4가 소비할 current-request context set.

4.3은 역할 모델을 호출하거나 협업 결과를 canonical memory로 저장하지 않는다.

### 4.4 — AC Ensemble Agent 연동 전처리·단일 소유권

상태: `VERSION_ASSIGNED_PLAN`

4.4는 AC Ensemble Agent가 standalone 제품을 유지하면서 Archive Center integrated mode를
선택할 수 있게 하고, 한 요청의 전처리 owner를 정확히 하나로 고정한다.

여기서 전처리 owner는 Go가 요청 시작 전에 선택·승인한 **단 하나의 실제
materialization/model-call 경로**를 뜻한다. 요청 mode, contract, budget, privacy, lifecycle과
fallback을 정하는 정책 소유권은 계속 Go에 있으며 플러그인으로 이동하지 않는다.

선행 조건:

- AC Ensemble Agent `standalone_complete`;
- 4.3 역할별 packet과 request fence;
- 공식 RisuAI current request·main draft·취소 lifecycle 관찰 계약.

주요 범위:

- standalone 또는 integrated mode를 요청 시작 전에 하나만 선택;
- versioned integrated-preprocessor claim과 Archive Center Go의 검증·승인;
- current request에 결속된 versioned Ensemble input contract;
- Archive Center Go가 승인된 current request owner를 `ac_ensemble`로 commit하면 같은 Go
  plan이 Archive Center Publisher 호출·plan·direct guidance를 정확히 0으로 처리;
- 연동하지 않은 요청에서는 Archive Center Publisher를 기존 설정대로 유지;
- stale·wrong-turn·wrong-branch·wrong-revision claim 거부;
- pre-dispatch commit과 명시적 preprocessor terminal failure;
- provider×role별 실제 전송 자료·privacy·비용·실패 단계 trace.

연동 실패 시 standalone으로 자동 전환하지 않는다. Archive Publisher와 Ensemble 전처리를
동시에 넣거나 부분 contract 뒤 Archive fallback을 겹쳐 넣지 않는다.

인계: commit한 request owner와 정확한 request/claim lineage를 4.5에 전달한다.

### 4.5 — Ensemble performance·최종문·displayed-final lifecycle

상태: `VERSION_ASSIGNED_PLAN`

4.5는 메인 모델 1차 출력 이후 Archive Center Go가 역할 선택·공개 범위·순서·반복·stop

따라 역할 호출과 결과 반환을 수행하도록 연결하는 단계다. 최종 표시본 하나만 canonical
admission 대상으로 확정한다.

주요 범위:

- `main_draft_observed`를 정사가 아닌 최초 장면 proposal로 취급;
- 감독관의 장면 압력·목표·사건 개시;
- 나레이터의 환경·공개 사건과 결과 갱신;
- Actor별 private context에 따른 실제 대사·행동·침묵·반응;
- role turn 뒤 검증된 공개 사건만 `public_scene_state`에 반영;
- 차단된 행동과 private reasoning의 다음 역할 전달 금지;
- Go 소유 역할 선택·순서·반복·stop reason;
- 완료된 공개 상태를 사용한 최종 장면 작성 1회;
- `main_draft_observed → rewrite_result_ready → displayed_final_confirmed → turn_admitted`;
- `final_source = rewrite_result | main_draft`와 postprocess terminal status;
- reroll·delete·cancel·branch·concurrent generation의 superseded/active-final parity;
- 실제 displayed final 하나만 Critic·memory·relationship·thread admission에 제출.

postprocess 실패 시 유효한 main draft가 있으면 실패 상태와 `final_source = main_draft`를
명시하고 원문을 보존한다. 이 finality 결정은 4.4의 preprocessor cutover와 섞지 않는다.

`displayed_final_confirmed`는 현재 일반 RisuAI Host에서 구현·검증된 능력으로 간주하지 않는다.
4.5의 통합 출시는 공식 Host가 노출한 lifecycle 사실 또는 동등하게 검증 가능한 명시적 receipt로
이를 확인한 뒤에만 완료 판정한다. 이 계획 문장은 현재 runtime에 새로운 중단 정책을 추가하지
않는다.

4.5는 standalone의 세 전문 전체 재작성 후보를 integrated Actor 상황극으로 가장하지 않는다.
역할의 중간 발언, quality memo, main draft 또는 rewrite candidate를 canonical source로 저장하지
않는다.

인계: source-linked role trace와 displayed-final receipt를 4.6 이후 실행 계층에 제공한다.

## 8. 아직 확정해야 하는 통합 결정

다음은 버전 목적을 바꾸는 항목이 아니라 구현 전에 owner와 versioned contract를 확정해야

결정 전에는 JavaScript fallback, 임의 DB table, model-name branch, 고정 Actor/round 수,

## 10. 변경 관리

- 버전 소유권을 옮길 때는 이 문서의 전체 버전 지도와 선행 관계를 같은 변경에서 수정한다.
- 상세 문서에 새 번호를 먼저 만들지 않는다.
- `AC Ensemble Agent`와 historical `Recomposer`를 같은 제품 이름으로 혼용하지 않는다.
- current source, regression, package, loaded RisuAI, real DB와 long-session 증거를 분리한다.
- 기능 완료를 주장할 때는 해당 버전 산출물의 실제 consumer와 displayed-final 영향을 함께
  기록한다.
- 문서 변경만으로 구현 또는 release 상태를 올리지 않는다.
