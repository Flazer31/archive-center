# Archive Center 4.1 기억 lifecycle·복구 로드맵

상태: `planned` — 4.0 release gate 이후 구현

대상: edit/delete/reroll/copy/move/branch, dependency invalidation, transaction·outbox,
reindex·rebuild, package·upgrade·fault recovery와 전체 live release closure

정본 관계:

- 3.9 관계·profile과 bounded Publisher 오류 안정화는
  [`3.9-character-memory-basic-publisher-roadmap.md`](3.9-character-memory-basic-publisher-roadmap.md)가
  소유한다.
- 4.0 recall·injection과 `publisher_plan.v2`의 `book_author + director` 출판사 복구는
  [`4.0-precision-recall-injection-roadmap.md`](4.0-precision-recall-injection-roadmap.md)가
  소유한다.
- 4.1의 lifecycle·복구·실환경 release gate는 이 문서가 소유한다.
- 4.6~5.0 고급 RP 지원은 4.1에서 검증된 read-only projection만 소비한다.

## 0. 결정

4.1은 새로운 기억 종류나 출판사 능력을 추가하는 버전이 아니다. 3.8~4.0에서 만든
time/state/perspective/relation/profile/recall/injection이 실제 RisuAI의 수정·삭제·리롤·분기와
DB·Vector·process 장애 뒤에도 같은 accepted source에서 정확하게 복구되는지 닫는 버전이다.

문서·schema·DTO·fixture 존재는 완료 증거가 아니다. source commit, test, package, loaded
artifact와 실제 RisuAI/MariaDB/Chroma 결과가 연결돼야 한다.

## 1. lifecycle domain

한 source 변경은 다음 의존 영역을 같은 revision graph로 다룬다.

- raw/effective input과 accepted final source;
- source envelope·acceptance·generation·revision;
- atomic memory·direct evidence;
- story clock·current/history state;
- perspective·speaker/listener·knower·visibility;
- relation·habit·profile·voice projection;
- Publisher input/plan/carry와 실제 used support refs;
- recall plan·injection plan·delivery lineage;
- MariaDB projection·outbox·Chroma generation·cache;
- optional lorebook reference snapshot/index;
- HUD·Explorer·audit ViewModel.

현재 표시된 final이 아닌 draft, streaming candidate, 실패한 rewrite와 stale Publisher plan을
accepted source로 사용하지 않는다.

## 2. source와 revision 규칙

- edit는 새 source revision을 만들고 이전 revision의 파생 결과를 current에서 제외한다.
- reroll은 같은 logical user turn의 새 assistant generation을 active-final로 전환하고 이전
  generation 파생 결과를 supersede한다.
- delete는 대상 source와 의존 파생 결과를 invalidated/tombstoned로 만들며 부분 삭제 성공을
  허용하지 않는다.
- branch는 shared ancestor와 branch-local tail을 구분하고 다른 branch의 current projection을
  재사용하지 않는다.
- copy/move/connect는 raw message index가 아니라 backend가 계산한 source baseline과 stable
  identity mapping을 사용한다.
- restart는 committed MariaDB revision·outbox·index generation에서 재개하고 process-local
  cache나 last-known plan을 authority로 사용하지 않는다.

## 3. transaction·outbox·동시성

raw accepted source 저장과 파생 작업은 분리할 수 있지만 다음을 보장한다.

- source commit 이전 파생 canonical write 0;
- 같은 dependency batch의 일부 operation 실패 시 해당 batch partial commit 0;
- DB commit 뒤 Vector 실패는 durable outbox로 retry;
- stale worker는 compare-at-commit revision fence에서 거부;
- retry와 duplicate callback은 idempotent;
- process kill·timeout·restart 뒤 committed source와 job 상태가 일치;
- migration·rebuild와 foreground turn이 같은 row/index generation을 dual-write하지 않음;
- Publisher·recall 장애가 raw source 내구 저장을 취소하지 않음.

fail-open은 사용자 응답과 독립 optional projection에만 적용한다. canonical mutation과 owner
cutover는 실패 시 이전 committed revision을 유지해야 한다.

## 4. dependency invalidation

source revision이 바뀌면 다음을 source dependency graph로 무효화·재계산한다.

1. atomic event/state/utterance/observation;
2. current state와 story clock;
3. perspective·knowledge path;
4. relation·habit·profile;
5. thread realization과 consequence;
6. search document와 vector;
7. recall/injection cache;
8. Publisher support·plan·focus/carry;
9. HUD/Explorer read model.

semantic merge나 중요도 갱신이 여러 source에 의존하면 단순 마지막 row 삭제로 복구하지 않는다.
영향 source와 필요한 선행 undo를 보고하고 검증된 dependency order로만 재구축한다.

## 5. reindex·rebuild

- MariaDB canonical source에서 전체 Chroma generation을 재구축할 수 있어야 한다.
- 부분 reindex는 대상 source/revision/dependency를 명시하고 unrelated generation을
  current로 바꾸지 않는다.
- schema·embedding model·normalization 변경은 새 generation에서 shadow 검증 뒤 원자적으로
  current pointer를 전환한다.
- rebuild 결과는 source row set, document count, item ID/hash, tombstone와 visibility
  fingerprint가 일치해야 한다.
- 중단·재시작·retry 뒤 duplicate vector와 missing current vector가 없어야 한다.
- Vector가 없어도 exact·lexical recall과 메인 저장·응답은 유지된다.

## 6. Publisher와 displayed-final lifecycle

4.0 `publisher_plan.v2`는 request-scoped proposal이며 canonical memory가 아니다.

- plan은 session/request/logical turn/branch/generation/revision/input digest와 source snapshot에
  결합한다.
- reroll·edit·delete·branch·새 generation에서 이전 plan·focus·carry를 재사용하지 않는다.
- explicit redirection은 current request에서 이전 focus를 해제한다.
- complete-turn과 Critic은 실제 displayed final 하나만 admission한다.
- final observation을 확인할 수 없으면 사용자 응답은 보존하되 canonical write는
  deferred/read-only로 둔다.
- Publisher failure, draft, rejected plan과 failed output candidate를 memory evidence로
  저장하지 않는다.

4.6~5.0에서 추가되는 advanced Publisher·audit도 이 lifecycle fence를 그대로 사용하며 별도
last-known plan cache를 만들 수 없다.

## 7. 선택형 lorebook lifecycle

4.0-G가 활성화된 경우에만 다음 항목이 4.1 release gate에 추가된다.

- entry edit/delete;
- character/chat/module scope 변경;
- module enable/disable와 교체;
- consent 철회·DB 접근 거부;
- partial catalog observation과 timeout;
- branch/copy/restart;
- index generation·rebuild;
- native activation unknown과 actual payload overlap.

한 번 읽지 못한 항목을 삭제로 해석하지 않는다. 완전 snapshot과 명시적 deletion evidence가
없으면 `observation_unknown`으로 유지하며 current prompt delivery에는 사용하지 않는다.

## 8. OS·package·upgrade

지원 Windows·Linux·macOS·Termux 경로에서 다음을 검증한다.

- fresh install;
- 기존 3.5/3.7/3.8~4.0 upgrade;
- `.env`, 사용자 DB와 Chroma data 보존;
- MariaDB·Chroma version compatibility;
- launcher health commit/rollback;
- package manifest·source commit·artifact hash;
- 부분 다운로드·권한 오류·포트 충돌·불완전 runtime;
- backup·restore와 rollback rehearsal.

실행 가능 source test와 package fixture를 실제 설치·loaded plugin·DB roundtrip 증거로 바꾸어
보고하지 않는다.

## 10. 필수 검증 matrix

- edit 후 old revision exact/vector/profile/Publisher 검색 0;
- reroll 후 old generation memory·relation·plan·Critic admission 0;
- delete 뒤 dependent state·profile·vector·cache·HUD 재노출 0;
- branch A 변경이 branch B current projection을 변경하지 않음;
- copy/move/connect에서 stable source/entity mapping과 private scope 보존;
- DB commit 성공/Vector 실패 뒤 outbox recovery;
- Vector 성공/DB rollback 상태의 current pointer 승격 0;
- stale worker compare-at-commit 거부;
- process kill과 restart에서 duplicate job/write/vector 0;
- full rebuild와 incremental 상태 fingerprint 동일;
- Publisher plan이 다른 request/generation/revision에서 cache hit 0;
- displayed-final 미관찰에서 Critic/canonical mutation 0;
- long session에서 K·privacy·latency·index size 추세;
- optional lorebook OFF에서 관련 lifecycle job 0;
- 각 지원 OS의 fresh/upgrade/fault/rollback.

## 11. 출시 중단 조건

- raw source보다 파생 row를 먼저 canonical commit;
- mutation batch partial apply;
- stale worker·old generation·wrong branch가 current로 승격;
- rollback 뒤 wrong-branch tail·vector·cache·carry 재노출;
- Chroma를 canonical truth 또는 유일 recall fallback으로 사용;
- displayed final이 아닌 draft·Publisher/Reviewer text를 Critic에 제출;
- actual DB/index/loaded RisuAI 없이 fixture만으로 live 완료 선언;
- 사용자 `.env`, DB, Chroma data를 package나 rollback이 덮어씀;
- JavaScript가 delete/reroll range, revision 또는 migration baseline을 계산;
- open/blocked requirement가 있는데 4.1 또는 3.6~4.1 전체 완료 선언.

## 12. 4.6으로의 인계

4.1은 4.6~5.0에 stable entity, direction/domain relationship, profile, source-backed
graph-neighborhood recall, thread realization, Publisher used refs와 lifecycle-safe read model을
제공한다.

후속 계층은 이를 read-only로 소비한다. 관계 graph·simulation·advanced Publisher가
canonical memory, relation, importance, profile, recall ranking과 lifecycle을 다시 쓰거나
별도 planner로 대체할 수 없다.
