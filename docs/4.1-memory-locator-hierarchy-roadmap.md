# Archive Center 4.1 기억 Locator·계층 탐색 로드맵

> 현재 지위: Locator의 상세 설계 근거지만 번호는 역사적이다. 새 통합 정본에서는 5.8이
> 이 범위를 소비한다. 4.1~9.0 버전 상태·선행 관계와 현재 4.0 계약명은
> [`4.1-9.0-integrated-roadmap.md`](../../_archive/future-reference/4.1-9.0-integrated-roadmap.md)를 우선한다.
> 현재 runtime 계약은 `memory_recall_plan.v1`, `memory_delivery_plan.v1`,
> `payload_application_plan.v1`과 `publisher_plan.v2`다.

상태: `detail_source_historical_numbering` — 새 4.8 상세 근거, 구현 승인은 별도

대상: 현재 질문·인물·사건·관계에서 출발해 어떤 기억이 어디에서 왔는지 찾고,
turn·episode·chapter·arc 계층과 source lineage를 사용자가 탐색하는 read-only 표면

정본 관계:

- recall·ranking·핵심 K·최종 injection·Publisher와 edit/delete/reroll/rebuild lifecycle은
  [`4.0-precision-recall-injection-roadmap.md`](4.0-precision-recall-injection-roadmap.md)가
  소유한다.
- 4.1은 4.0이 확정한 source pointer와 read model을 탐색 가능하게 보여준다.
- 위험 semantic merge·격리·검토·undo는 4.2가 소유한다.
- 관계 graph·simulation owner는 4.6 이후이며 4.1의 계층 탐색을 canonical graph로
  승격하지 않는다.

## 0. 결정

4.1은 새 기억 원장, 두 번째 검색기 또는 상시 agent memory를 만드는 버전이 아니다.
4.0 검색에서 이미 사용한 exact source pointer, hierarchy 좌표와 found/not-found trace를
사용자가 이해하고 재현할 수 있는 Go ViewModel로 제공한다.

Locator가 찾았다는 사실은 기억의 진실성·중요도·관계·현재성을 새로 승인하지 않는다.
찾지 못했다는 사실도 “그 사건은 존재하지 않는다”는 canonical 판정이 아니다.

## 1. Locator 계약

한 locator record는 최소한 다음을 가진다.

- session·branch·request와 source revision;
- subject·claim·question 또는 exact ref;
- source kind와 stable source pointer;
- turn·episode·chapter·arc hierarchy 좌표;
- entity·time·knower·visibility·authority·lifecycle;
- found/not-found/degraded 상태와 이유;
- 사용한 exact·lexical·vector·hierarchy lane;
- current 재사용 가능 여부와 expiry/fence;
- confirmed worldline owned turn range와 family별 inheritance 상태;
- 원문·요약·파생 표현 사이의 retained lineage.

query, scope, revision, branch, knower, visibility와 expiry가 모두 맞을 때만 같은 locator를
재사용한다. 하나라도 바뀌면 4.0 owner에 새 조회를 요청하고 과거 결과를 current로
재사용하지 않는다.

## 2. 계층 탐색

탐색은 다음 방향을 모두 지원하되 MariaDB source와 4.0 hierarchy projection을 읽기만 한다.

1. 현재 전달 item → source turn·원문·근거;
2. turn → episode → chapter → arc 상향 zoom;
3. arc/chapter → 포함 turn과 source 하향 zoom;
4. 인물·관계·사건 → 연결 source와 시점;
5. selected → rendered → delivered lineage;
6. excluded/deferred → 제외 이유와 부족한 좌표;
7. current projection → superseded/tombstoned history 비교.

상위 요약을 하위 사실의 대체 원문으로 사용하지 않는다. 계층 zoom은 탐색 범위를 바꾸는
것이지 canonical fact, relevance score나 핵심 K를 다시 계산하는 기능이 아니다.
episode·chapter·arc summary는 child source coverage와 open-tail/blocked 상태를 표시하고,
요약이 얇거나 충돌하면 하위 source로 내려가는 escape hatch를 제공한다.

## 3. Search·ViewModel 경계

- Go가 locator query, scope validation, hierarchy traversal과 ViewModel을 소유한다.
- JavaScript는 검색 조건 전달, backend 결과 표시와 사용자의 이동 동작만 담당한다.
- Chroma hit는 MariaDB source pointer로 hydration·validation된 뒤에만 표시한다.
- Chroma search hit의 text preview·trace도 confirmed branch owned turn range를 통과한 뒤에만
  표시한다. main-model payload에서 제외됐다는 사실만으로 Locator/UI 비누출을 주장하지 않는다.
- negative trace는 query·scope·사용 가능 lane을 함께 표시한다.
- vector/graph 장애가 있으면 degraded lane을 보여주되 scope·privacy·K를 넓히지 않는다.
- source 원문과 private memory는 기존 visibility·reveal ceiling을 그대로 따른다.

## 4. 금지 범위

- canonical fact·raw chat·전체 대화 사본을 별도 Locator DB에 복제;
- 조회 빈도·최근 조회·similarity를 importance 또는 truth로 승격;
- not-found를 deletion·absence·contradiction으로 저장;
- 계층 pointer를 새 relation·entity ID로 해석;
- Locator UI에서 admission·merge·delete·revision을 직접 변경;
- JavaScript에서 search ranking, hierarchy range 또는 visibility를 계산;
- 4.0의 `memory_recall_plan.v1`·`memory_delivery_plan.v1`·
  `payload_application_plan.v1`을 재구현하거나 v2로 임의 승격.

| packet | 단일 책임 | 완료를 막는 exit evidence |

## 6. 필수 검증

- 같은 이름의 다른 인물·공유 별칭 source 교차 표시 0;
- wrong session·branch·revision·knower·visibility locator 재사용 0;
- parent post-fork·sibling·copied-prefix source가 result, vector preview, trace, export와 source 이동
  어디에도 current item으로 노출되지 않음;
- edit·delete·reroll 뒤 이전 locator current 재노출 0;
- selected item에서 실제 delivered payload와 source 원문까지 동일 ref로 이동;
- deferred/excluded item의 이유가 4.0 plan과 일치;
- turn→chapter→turn 왕복 뒤 source set과 정렬이 재현됨;
- hierarchy summary마다 child-source coverage·open-tail·blocked reason이 재현되고, summary-only
  text가 canonical source를 대체하지 않음;
- vector OFF에서 exact·lexical·hierarchy 탐색 유지;
- not-found 이후 새 source가 생기면 이전 negative trace를 current 사실로 재사용하지 않음;
- private memory와 reveal ceiling이 Explorer에서도 동일하게 적용;
- 장기 session에서 locator cache·ViewModel이 무제한 증가하지 않음.

## 7. 출시 중단 조건

- Locator를 canonical memory나 두 번째 검색 owner로 사용;
- source pointer 없이 요약 text만 표시하거나 이동;
- stale·wrong-branch·tombstoned source가 current 결과로 노출;
- vector/graph 장애 시 전체 raw chat 또는 더 넓은 private scope로 우회;
- JavaScript가 source range·ranking·visibility·lifecycle을 결정;
- 4.0의 검색·주입 결과와 다른 item을 “실제 전달 기억”으로 표시;
- source fixture만으로 loaded RisuAI·실제 DB 완료를 선언.

## 8. 4.2로의 인계

4.1은 4.2에 stable source pointer, dependency lineage, current/superseded 상태와 영향 범위를
전달한다. 4.2의 정리·격리·검토·undo는 이 read model을 사용하되 4.1 UI에서 canonical
mutation을 직접 수행하거나 4.0 lifecycle owner를 우회하지 않는다.
