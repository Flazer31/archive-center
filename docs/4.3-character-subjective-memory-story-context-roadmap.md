# Archive Center 4.3 역할별 이야기 문맥·인물별 주관 기억 강화 로드맵

> 현재 지위: 역할별 packet과 주관 기억의 상세 설계 근거지만 번호는 역사적이다.
> 새 통합 정본에서는 주관 기억 근거를 5.1~5.7이, 역할별 packet을 6.1이 소비한다.
> 확장 제품의 현재 정본 이름은 `AC Ensemble Agent`이며 6.1~7.0 통합 소유권과 현재 구현
> 경계는 [`4.1-9.0-integrated-roadmap.md`](../../_archive/future-reference/4.1-9.0-integrated-roadmap.md)를 우선한다.
> 아래 Recomposer 이름은 작성 당시의 가칭 또는 역사적 wire contract 문맥으로만 읽는다.

상태: `planned` — 버전 배정과 필요성 확정, 세부 계약 이름은 구현 전 확정

대상: Archive Center 기억과 RisuAI 로어북·캐릭터·페르소나 정보를 결합한 역할별 문맥,
인물별 주관 기억의 정확한 회수, 별도 다중 AI 플러그인에 전달할 read-only 연동 계약

정본 관계:

- canonical source, 기억 선택·예산·privacy·lifecycle은
  [`4.0-precision-recall-injection-roadmap.md`](4.0-precision-recall-injection-roadmap.md)가
  소유한다.
- 기억 위치와 source 계층 탐색은
  [`4.1-memory-locator-hierarchy-roadmap.md`](4.1-memory-locator-hierarchy-roadmap.md)가
  소유한다.
- 4.3은 4.0의 기억과 RisuAI가 실제로 제공한 로어북·캐릭터·페르소나 정보를 전체 이야기
  역할과 인물별 관점에 맞게 배분한다.
- `Recomposer`는 역사적 가칭이고 현재 확장 제품 이름은 `AC Ensemble Agent`다.
- AC Ensemble Standalone은 `main_draft`를 전문 작성자·비평가·final composer가 개선하는
  별도 경로다. Integrated 4.3~4.5는 그 rewrite pipeline이 아니라 나레이터와 장면 관련 Actor
  AI가 서로 다른 기억을 받아 순차 role turn으로 실제 장면을 연기하는 mode다.
- 4.4는 Integrated 무대 진입·Archive Center Publisher 자동 OFF·역할 입력 계약, 4.5는
  narrator/Actor performance·transcript assembly·displayed-final lifecycle을 소유한다.

## 0. 결정

모든 역할 AI가 같은 전체 기억 묶음을 받게 해서는 안 된다. 나레이터는 현재 장면과
전체 이야기의 공통 흐름, 공개된 기억과 세계 상태를 받아야 한다. 연기자는 같은 배경
이야기를 공유하되 자신이 경험했거나 들었거나 추론한 내용, 현재 감정·관계·목표 등 자신에게
속한 주관 기억만 별도로 받아야 한다.

“전체 스토리를 기억한다”는 모든 원문을 매번 전송한다는 뜻이 아니다. accepted source에서
만든 arc·chapter·episode·turn 계층, 현재 장면, 중요한 원인·결과, 미해결 약속과 진행 중인
thread를 예산 안에서 조립하고 필요한 source ref를 연결한다.

Integrated에서 역할 AI는 같은 초안을 평가하는 reviewer가 아니다. 나레이터의 공개 발언과
검증된 공개 장면을 보고 Go가 고른 다음 Actor가 자기 perspective packet으로 실제 대사·행동·
침묵·반응을 생성한다. 이 공개 role turn들의 누적 transcript가 최종 장면의 주 재료다.

## 1. 입력 자료와 시간 경계

### 1.1 RisuAI Host 문맥

별도 플러그인의 Integrated 입력 준비는 RisuAI가 현재 요청에서 실제로 제공하거나 공식 Host API로
관찰할 수 있는 다음 자료를 사용한다.

- 현재 캐릭터 정보와 현재 사용자 페르소나;
- 현재 요청에 실제로 포함된 활성 로어북·시나리오·작가 노트 범위;
- 현재 사용자 입력, 최근 대화와 요청 좌표;
- 각 자료의 Host 출처, 적용 범위와 관찰 시점.

Archive Center는 RisuAI 로어북 발동 엔진을 복제하거나 전체 로어북을 별도 판정하지 않는다.
Host가 노출하지 않은 활성 여부를 이름·문구·내용으로 추측하지도 않는다.

### 1.2 공통 배경 이야기와 공개 기억

나레이터와 참여 연기자가 공유할 수 있는 문맥은 다음으로 제한한다.

- 현재 session·branch의 이야기 전제와 사용자 방향;
- arc·chapter·episode 단위 흐름과 현재 위치;
- 현재 장면의 시간·장소·공개된 사건;
- 이미 실현된 결과와 아직 해결되지 않은 약속·갈등·목표;
- 공개된 인물·세력·세계 상태;
- 이번 staged performance가 이어받아야 하는 현재 응답 의무;
- 각 항목의 source·revision·time·authority·lifecycle.

공통 문맥은 어느 인물도 알 수 없는 private fact, 다른 인물의 속마음과 미공개 계획을
포함하지 않는다.

### 1.3 인물별 주관 기억

각 연기자의 packet은 그 인물이 가질 수 있는 다음 기억만 포함한다.

- 직접 경험한 사건과 자신이 들은 발언;
- 사건에 대한 해석·오해·의심·편견·거짓 기억;
- 다른 인물에 대한 방향별 관계 기억;
- 감정의 원인, 현재 목표·두려움·욕구·미해결 의무;
- 자신이 알고 있는 세계 규칙과 모르는 정보;
- 최근 장면에서의 판단과 행동 연속성;
- 해당 관점을 지지하거나 반박하는 source-linked 근거.

objective truth와 subjective belief를 한 문장으로 합치지 않는다. 인물의 믿음이 틀렸더라도
그 믿음 자체는 주관 기억으로 보존할 수 있지만, 공통 이야기의 사실로 승격하지 않는다.

### 1.4 순간·장면·장기 기억 경계

- 순간·최근 대화는 RisuAI가 실제 current request에 제공한 context를 사용한다. Archive
  Center는 같은 raw chat을 역할 수만큼 복제하거나 별도 단기 기억 owner를 만들지 않는다.
- 장면 상태는 current scene, 공개 role-turn transcript, active state·thread를 request-scoped로
  묶고 session·branch·logical turn·generation·revision fence를 적용한다.
- episode·chapter·arc와 장기 source는 계층 요약과 필요한 근거만 제공하며, 상위 요약이
  Actor별 무지·오해·private memory 또는 하위 canonical source를 덮어쓰지 않는다.
- character-specific 회상 강도·망각·재활성화는 향후 Actor projection의 책임이며 canonical
  world memory 삭제나 전역 importance 감소로 표현하지 않는다.

## 2. 역할별 AI 할당

### 2.1 Go 장면 오케스트레이션·나레이터

- Go는 source-linked 전체 배경, 현재 장면의 목표·갈등·제약과 미해결 thread에서 허용
  context와 다음 역할을 계산한다. 이 계산을 별도 감독관 AI의 문장에 맡기지 않는다.
- 나레이터 역할에는 전체 배경 이야기, 공개된 세계·시간·장소·사건과 서술 연속성을
  전달한다.
- 나레이터는 특정 인물만 아는 private memory를 객관적 사실처럼 받지 않는다.
- 선택적 감독관 모델을 나중에 사용하더라도 보조 proposal owner일 뿐 필수 배역, canonical
  판정자 또는 narrator/Actor role-turn 대체가 아니다.

### 2.2 연기자

- 내부 stable entity ID는 packet routing과 lineage에만 사용한다.
- AI에게 보이는 입력은 이름·역할·관계와 자연어 기억으로 렌더링하며 의미 없는 내부 ID를
  prompt 본문에 반복하지 않는다.
- 같은 인물의 별칭은 하나의 owner로 연결하되 동명이인·역할명·집단명을 자동 병합하지 않는다.
- 참여 연기자는 현재 장면, 나레이터/누적 공개 transcript가 만든 영향, 미해결 관계와 명시적
  사용자 요청을 근거로 선택한다.
- 현재 장면과 무관한 모든 연기자 AI를 항상 호출하지 않는다.
- 역할별 모델·endpoint·추론 강도와 호출 여부는 별도 플러그인 설정이 소유한다.
- Archive Center는 provider 설정을 복제하지 않고 각 역할에 전달할 기억·근거·가시성만
  확정한다.

## 3. 전체 이야기 문맥 조립

공통 이야기 문맥은 다음 순서로 조립한다.

1. RisuAI가 현재 요청에 실제로 적용한 캐릭터·페르소나·활성 로어북·시나리오 문맥;
2. 현재 사용자 방향과 장면 좌표;
3. 현재 arc와 가까운 narrative goal;
4. 직전 장면과 이미 실현된 결과;
5. 관련 chapter·episode 요약;
6. 현재 인물·관계·세계 상태;
7. 미해결 약속·갈등·thread;
8. 4.0이 선택한 관련 source-linked 기억과 직접 근거;
9. 비밀·사용자 agency·must-not 경계.

현재 사용자 입력과 Integrated가 이미 확정한 공개 role-turn transcript는 4.4·4.5 계약에서
손실 없이 전달한다. 과거 원문은 관련 source가 필요한 경우에만 읽고, 전체 대화 원문을 agent
수만큼 복제하지 않는다.

`scene`은 단순 turn 개수나 요약 구간의 별칭이 아니다. 구현 전 source-linked
open/continue/close reason, current scene range, branch·revision과 narrator/Actor turn 포함 범위를
확정한다. 이 결정은 새 저장소를 자동 승인하지 않으며 기존 state/thread/hierarchy owner를 먼저
확장할 수 있는지 검토한다.

## 4. 주관 기억 강화 규칙

- owner·knower·listener·visibility가 확인된 기억을 우선한다.
- 동일 사건의 objective event와 인물별 interpretation을 함께 연결하되 서로 덮어쓰지 않는다.
- 현재 감정만 보내지 않고 그 감정의 source-backed 원인을 함께 제공한다.
- 관계는 상대·방향·domain별로 분리하고 자동 상호성을 만들지 않는다.
- 오래된 믿음이 수정됐으면 current와 history를 구분하고 최신 accepted revision을 사용한다.
- 기억이 부족하면 빈칸을 다른 인물의 기억이나 모델 추론으로 채우지 않는다.
- 인물이 모르는 사실은 `unknown`으로 유지하고, 다른 agent가 아는 사실을 자동 공유하지 않는다.
- 전체 이야기 요약이 인물별 무지·오해·비밀 경계를 덮어쓰지 않는다.

## 5. 연동 packet

아래 이름은 목적을 설명하기 위한 가칭이며 플러그인 이름·역할 구조와 함께 바뀔 수 있다.

- `risu_roleplay_context_snapshot.v1`: RisuAI가 실제로 제공한 로어북·캐릭터·페르소나·현재
  요청 문맥;
- `story_context_snapshot.v1`: 모든 참여 agent가 공유 가능한 전체 이야기 문맥;
- `scene_context_snapshot.v1`: 현재 요청·최근 공개 context·장면 좌표·응답 의무와 performance
  시작 상태;
- `character_perspective_packet.v1`: 한 인물에게만 할당되는 주관 기억·관계·목표·무지;
- `role_agent_roster.v1`: 이번 요청의 나레이터·연기자와 선택적 비공연 보조 역할,
  packet·source lineage;
- `agent_context_assignment.v1`: 어느 역할이 어떤 Host·공통·개별 context를 받았는지 기록.

각 packet은 session·branch·logical turn·generation·revision·request와 input-plan hash에
결합한다. stale packet, wrong branch packet과 이전 performance의 packet을 다음 요청에
재사용하지 않는다.

## 6. 대화·저장 권한 경계

- 4.3은 기억과 Host 문맥을 선택·할당할 뿐 역할 AI performance를 실행하지 않는다.
- 나레이터·연기자 AI의 미표시 발언, private reasoning과 차단된 proposal은 canonical
  memory가 아니다. 공개 role turn도 최종 displayed transcript와 admission을 통과하기 전에는
  canonical assistant turn이 아니다.
- agent가 새 사실·관계·감정·사건을 주장해도 accepted displayed final과 Critic admission을
  통과하기 전에는 DB에 사실로 저장하지 않는다.
- Go가 각 role turn의 사용 가능 근거와 공개 범위를 확정한다. 별도 플러그인은 승인된 packet을
  넓히지 않고 역할 호출·결과와 lineage를 반환해야 한다.
- 한 agent의 제안을 전체 이야기의 정답이나 사용자 행동으로 강제하지 않는다.
- Archive Center base 기억·저장·본문 생성은 별도 플러그인이 설치되지 않아도 독립적으로
  작동해야 한다.

## 8. 필수 검증

- RisuAI가 실제 적용한 로어북·캐릭터·페르소나만 포함되고 비활성 항목을 추측하지 않음;
- 나레이터는 전체 배경 이야기와 공개 기억을 받고 인물 private memory는 받지 않음;
- 동일 사건을 서로 다르게 기억하는 두 연기자의 packet이 분리됨;
- 한 인물만 아는 비밀이 다른 인물과 공통 문맥에 들어가지 않음;
- 틀린 믿음이 objective truth로 표시되지 않음;
- 관계 방향 A→B와 B→A가 자동 복제되지 않음;
- current emotional state와 그 원인 source가 함께 전달됨;
- arc·chapter·episode 요약에서 현재 장면과 미해결 thread가 이어짐;
- 전체 raw history를 agent마다 복제하지 않음;
- 동명이인·공유 별칭·역할명에서 packet owner 교차 0;
- edit·delete·reroll·branch 뒤 이전 packet 재사용 0;
- agent 대화·제안이 canonical DB에 직접 저장되는 경우 0;
- narrator 공개 발언 뒤 장면 관련 Actor가 선택되고, 그 Actor가 누적 공개 transcript와 자기
  perspective만 받으며 다른 Actor의 private memory·reasoning을 받는 경우 0;
- 고정 Actor 수·고정 round-robin·모든 캐릭터 무조건 호출 0;
- 별도 플러그인 미사용에서 Archive Center base payload·Publisher·저장·HUD 비퇴행;
- 실제 다인물 장기 RP에서 기억 정확도·배역 행동 차이·입력량·비용·최종 transcript 품질 증거
  분리. 호출 수 자체를 RP 개선 증거로 사용하지 않음.

## 9. 4.4·4.5로의 인계

4.3은 4.4에 RisuAI Host 문맥, 공통 배경 이야기, 역할별 공개 기억, 인물별 perspective
packet, 역할 roster와 request fence를 전달한다. 4.4는 별도 플러그인이 단독형을 유지하면서
Archive Center Integrated 무대 진입을 맡고, 그 요청의 Archive Center Publisher를 자동 OFF하며,
scene context와 각 role turn을 동일 request lineage에 연결하는 계약을 확정한다.

4.5는 나레이터가 공개 장면을 열고, Go가 장면에 관련된 다음 Actor를 고르며, 각 Actor가
허용된 4.3 packet과 누적 공개 transcript를 받아 실제 대사·행동으로 응답하는 순차 performance를
실행한다. 검증된 공개 role turn은 `performance_transcript`를 이루고, 마지막 assembler는 이를
창작적으로 다시 쓰지 않고 하나의 RisuAI 응답으로 배열한다. 4.5는 displayed-final receipt와
기억 저장 lifecycle을 닫는다.
