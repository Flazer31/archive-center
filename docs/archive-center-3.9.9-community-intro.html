3. 보존 폴더를 만들고 DB를 복사합니다

4. 복사본을 확인합니다
test -d "$BACKUP_DATA/mariadb-data/mysql" && echo "MariaDB 백업 확인" || echo "MariaDB 백업 실패"

10 / 이후 버전 자동 업데이트
3.9.9 이후에는 설정에서 지금 업데이트 한 번
3.9.9는 이후 버전으로 직접 올라가기 위한 자동 업데이트 기준점입니다. 사용자는 운영체제, 프로세서 종류, 내려받을 파일 이름, 파일 검증값과 DB 변경 파일을 직접 고르지 않습니다. 설정의 업데이트 확인에서 새 버전을 찾은 뒤 지금 업데이트를 누르면 필요한 과정이 이어서 실행됩니다.
업데이트 버튼을 누른 뒤 진행되는 작업
01실행 중인 백엔드가 자신의 운영체제와 프로세서 종류에 맞는 GitHub 배포 패키지 선택
02SHA-256 검증값, 패키지 버전, 관리 파일 전체 목록과 DB 변경 목록 확인
03새 파일 추가, 변경 파일 교체, 이전 목록에만 남은 관리 파일 제거
04모든 SQL DB 변경을 이름순으로 적용하고 프로그램에 포함된 DB 구조 작업 실행
05새 백엔드가 정상 준비 상태인지, 실행 버전이 내려받은 버전과 정확히 같은지 확인한 뒤 업데이트 확정
06새 버전 시작이나 상태 확인이 실패하면 프로그램 관리 파일만 이전 버전으로 복구
MariaDB·ChromaDB 데이터와 사용자의 환경 설정·비밀값은 프로그램 관리 파일에 포함하지 않으며 프로그램 파일 복구 대상으로 삼지 않습니다. DB 구조 변경은 기존 항목을 바로 지우거나 바꾸지 않고 새 항목을 먼저 추가하는 방식으로 적용해, 큰 버전 차이를 건너뛰는 업데이트에서도 기존 데이터를 이어서 읽습니다.
