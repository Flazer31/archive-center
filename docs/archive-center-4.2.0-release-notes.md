# Archive Center 4.2.0

4.2.0은 현재 장면에 필요한 기억을 선택하는 과정과 저장 진행 표시를 개선합니다.

## 주요 변경

- 사실마다 관련성·중요도·RP 턴 최신성을 최종 순위에 반영합니다. 한 기록의 검색
  점수를 모든 자식 사실에 복사하지 않고, 의미 유사도를 해당 사실에 연결합니다.
- 현재 입력과 최근 사용자·최종 AI 응답 쌍을 검색 질의로 활용합니다. 최근 원문을
  기억 본문에 중복 주입하지 않습니다.
- 완성 턴 요약과 사건·인물 객관 상태·주관 기억/관계·세계 상태·미해결 목표에
  핵심 기억 최대 수를 각각 적용하며, 자료별·전체 문자 예산을 유지합니다.
- 명시적으로 완료된 사건의 열린 목표 갱신, 재색인 중 상태 중복 저장,
  서로 다른 배열 사실의 식별 충돌, 원문만 남은 턴의 평론가 재개를 수정했습니다.
- 저장 확정 시점에서 **현재 턴**(기본: 응답 직후)과 **이전 턴**(다음 새 입력에서
  직전 응답 확정)을 선택합니다. 이전 턴 모드의 마지막 응답은 다음 입력까지
  확정 대기로 남으며, 현재 생성은 직전 평론가 처리를 기다리지 않습니다.
- 이전 턴 모드의 HUD를 현재 생성과 직전 평론가·저장 두 카드로 나누고,
  6+6 단계 표시·완료 카드 닫기·자동 복구 카드의 X 닫기를 보완했습니다.
  복구 카드 닫기는 평론가 복구 작업을 취소하지 않습니다.
- 검색 결과 수·핵심 기억 최대 수·최근 대화 참고 수를 구분하고, PDF 전달 방식과
  저장 확정 시점을 일반 설정에서 확인하도록 정리했습니다.

4.1의 요청 재시도·리롤 교체·Text/PDF 전달·Yumi Translator 원문 호환은 유지합니다.
새 DB 마이그레이션이나 기억 점수 계산용 추가 AI 호출은 도입하지 않았습니다.

## 처음 설치

Windows ZIP을 직접 내려받았다면 빈 폴더에 압축을 풀고
`01_start_archive_center_windows.bat`를 실행합니다. 필요한 런타임 준비 후
백엔드가 실행됩니다.

Windows PowerShell 한 줄 설치:

```powershell
irm https://raw.githubusercontent.com/Flazer31/archive-center/main/install-windows.ps1 | iex
```

Linux, macOS, Termux 한 줄 설치:

```sh
curl -fsSL https://raw.githubusercontent.com/Flazer31/archive-center/main/install.sh | sh
```

한 줄 명령은 신규 설치 전용입니다. 기존 설치를 발견하면 덮어쓰지 않고 업데이트
경로를 안내합니다. RisuAI에는 패키지의 `Archive Center.js`를 설치하고 백엔드에 연결합니다.

## 기존 설치 업데이트

- 관리형 설치는 Archive Center 설정의 **업데이트 확인 → 지금 업데이트**를 사용합니다.
- Windows는 전용 Update Package를 우선 사용하며 Linux·macOS·Termux는 각 OS와
  CPU에 맞는 Auto Install Package를 설치와 업데이트에 함께 사용합니다.
- 관리 파일을 교체한 뒤 누적 마이그레이션을 적용하고, 새 백엔드의 준비 상태와
  정확한 버전을 확인합니다. DB·런타임 데이터·로컬 환경 설정·키는 교체 대상이 아닙니다.
- 시작이나 준비 확인에 실패하면 관리 파일을 복구합니다. DB를 과거 상태로 되돌리는
  작업은 하지 않으며, 4.2의 마이그레이션 입력은 4.1과 동일합니다.
- RisuAI에 설치된 플러그인은 RisuAI의 플러그인 업데이트 기능 또는 새 파일 가져오기로
  갱신하십시오. 백엔드 패키지 교체만으로 RisuAI의 설치된 코드가 바뀌지는 않습니다.

## 배포 대상

Windows x64 설치·업데이트 ZIP, Linux x64/arm64, macOS Intel/Apple Silicon,
Termux arm64의 7개 ZIP과 `SHA256SUMS-4.2.0.txt`를 제공합니다.
Windows arm64는 이번 릴리스의 네이티브 배포 대상이 아닙니다.

각 OS의 빌드·패키지 검사와 실제 기기에서의 설치·사용 검증은 구분합니다.
전체 실사용 조합의 무오류나 기억 품질·토큰 절감 수치는 보장하지 않습니다.

## 패키지 검증

- JavaScript 구문, 전체 Go 테스트와 정적 검사 통과.
- Windows 신규 설치 계약과 생성된 POSIX 패키지 실행기 계약 검사 통과.
- 7개 ZIP의 버전·파일 해시·CPU 형식·실행 권한과 사용자 상태 미포함 확인.
- 실제 공개 4.1 패키지 7개에서 4.2 업데이트 사전검증 통과.
- Windows 4.1 업데이터의 실제 적용·복구·재적용·확정과 테스트 설정/runtime 보존 확인.
- Windows 패키지의 격리 시작·준비 상태 검사 통과.
- 릴리스 소스의 Windows·Ubuntu·macOS GitHub CI 모두 통과.
- 격리 Windows 환경에서 실제 공개 4.1 → 4.2 관리형 업데이트와 재시작·확정 통과.
  실제 MariaDB 대화·기억, ChromaDB 문서·벡터 검색, 로컬 설정 보존 확인.

검증 범위와 별도 확인이 필요한 환경은 [공개 및 업데이트 검증 기록](archive-center-4.2.0-release-verification.md)에 정리했다.
