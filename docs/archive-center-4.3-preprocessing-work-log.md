## 2026-09-08 — 다섯 기억 편집자의 프롬프트와 요청 이유 전달

유지하지만, 임의 모델이 쓴 이유의 의미까지 자동으로 비밀 누출 없이 판정한다는 뜻은 아니다.

## 2026-09-08 — 완료 HUD 펼치기와 닫기 구분

정상 완료 HUD는 본체나 X 클릭으로 닫고, 상세 펼치기/접기는 그대로 유지한다.

경고·오류·복구 카드의 X 전용 동작은 유지하며, 정상 완료된 이전 저장 카드의 X도 보존한다.

공식 RisuAI `c454df882aaf32e02a22da26d3718c8cadc97814`의
[`SafeElement`](https://github.com/kwaroran/RisuAI/blob/c454df882aaf32e02a22da26d3718c8cadc97814/src/ts/plugins/apiV3/v3.svelte.ts)와
`risuai.d.ts`를 2026-09-08 확인했다. 클릭 콜백은 document 이벤트의 좌표만 전달하며,
실제 DOM target이나 `stopPropagation()`을 노출하지 않는다. 기존 닫기 함수에서
`querySelectorAll('details[open]')`와 `SafeClassArray.length()`로 펼친 항목 수 변화를
읽어 기본 HTML 토글과 닫기를 구분한다. 중앙 고정 HUD가 토글 직후 움직여도 동일하게
처리한다. 기존 클릭 리스너 한 개와 동일 인스턴스의 정리를 유지하고 타이머·관찰자를
추가하지 않았다. UI 안의 임시 관측이며 요청 수락·저장·백엔드 상태는 변경하지 않는다.

기존 생산 Host 회귀에 정상 본체 클릭·토글·바깥 클릭·X 동작을 반영했고, 수정 전
정상 본체 클릭이 닫히지 않는 실패를 기록했다. 실제 Edge의 HTML 토글과 공식 형태의
비동기 DOM 경계에 생산 닫기 함수를 연결하여 펼치기/접기, Enter/Space, 일반 영역,

같은 생산 닫기 함수를 연결했다. 로드된 RisuAI에서 보고된 즉시 닫힘의 정확한 실행 버전은

## 2026-09-07 test.15 — 담당별 해석의 독립 전달

- `multiAgentInput()`의 후보와 `runMultiAgent()`의 공개 근거 전달에 기존 `source_table`을
  함께 실었다. 기존 `reference_format`에 출처 턴과 누적 상태 갱신 턴의 의미를 설명한다.
  사용자 편집 프롬프트가 있어도 자료 형식 설명은 함께 전달된다.
- `buildPrepareTurnPriorityMemoryDeliveryPlan()`은 해당 상태에만
  `[state snapshot turn N; fields may be older]`를 붙인다. 원문·ID·출처 턴·점수는
  그대로이며, 필드별 시점을 추측하거나 오래된 필드를 삭제하지 않는다. 기존 출판사
  지원 자료와 최종 Go 기억 계획에도 같은 표시가 전달된다.
- 공통 기본 전처리 프롬프트와 기본 출판사 프롬프트는 '이미 확인한 완료'와 '알 수 없는
  시각 등 세부 내용'을 구분하도록 보완했다. 수량·소유자·위치를 각각의 근거와 연결하며
  사용자의 설정 변경·새로운 이야기 진행 권한과 저장된 사용자 프롬프트를 보존한다.
- 출판사가 test.12에서 긴장도 외 가이드를 생성하지 않았는지, 생성 후 처리에서 빠졌는지는
  원래 출판사 응답이 없어 미확정이다. 이를 가정하여 파서나 가이드 수락 규칙을 변경하지 않았다.

### 최근 대화 설정과 검색 경로 확인

UI `recentConversationReferenceCount` → 요청의 `recent_conversation_reference_count` →
`prepareTurnRecentConversationReferenceLimit()` 경로를 확인했다. 기본값은 5다.
`handlePrepareTurn()`이 받은 최근 대화를 검색과 전처리에 공급하며, 설정 수는
완결 대화의 최대 개수다. 각 대화에 관측된 사용자 입력과 AI 응답을 함께 유지하고,
이번 입력은 별도로 전달한다. 전처리의 두 차수 모두 같은 설정을 사용한다.

초기 검색과 담당의 보충 질문은 기존 Go 검색 소유자를 사용한다. ChromaDB는 의미 검색,
MariaDB는 정본 기억과 상태의 원문 연결을 담당한다. 전처리 AI는 현재 입력·최근 대화·
후보를 읽어 필요한 기억과 추가 질문을 고른다. 검색 결과와 AI 선정은 같은 단계가 아니다.
Chroma 설정/임베딩/검색 실패는 기존 진단과 동작을 유지하며 성공으로 가정하지 않는다.

## 동작과 소유권

사용자 선택에 따라 **5개 담당**으로 시작한다. 추가 기능의 독립 항목이며 기본 OFF다.
사건·진행 이력, 인물의 객관적 상태, 개인 경험·관계·비밀, 세계·장소·물건,
미해결 목표·복선을 담당한다. 개인 경험·관계 담당이 누가 무엇을 알고 있는지,
믿는지, 모르는지와 비밀 공개 범위를 다룬다. 모든 담당의 공통 지침에도 같은
원칙이 있으며 기존 Go의 관점별 읽기와 보호 기억 주입을 계속 사용한다.

`handlePrepareTurn()`에서 기존 검색·공개/관점별 투영으로 만든 후보를 최종 선정
전에 담당별 입력으로 만든다. 현재 입력과 기존 설정의 최근 대화, 출처 ID, 원문,
시점, 관점/공개 범위를 전달한다. 전체 DB를 각 AI에 통째로 보내지 않는다.

1. 사용 중인 담당 N개를 병렬 호출한다.
2. 누락 근거 또는 다른 담당에 대한 질문을 Go의 기존 벡터 검색 및 정본 수화로
   처리한다. 기존 세션/분기 이력 범위를 유지한다. 원래 사용자 입력의 순위 기준은
   추가 검색 질문으로 바꾸지 않는다.
3. 필요한 담당 M개만 보충 분석을 병렬 호출한다. 첫 추천과 새 근거를 함께 주며,
   새 검색 결과가 기존 입력 한도 뒤에 가려지지 않도록 먼저 보여준다.
4. Go가 최종 추천 ID를 정본 원문으로 렌더링한다. 기존 출판사가 실제로 주입할
   기억을 받아 서사 가이드를 만들고, 기존 Host 경로가 실제 요청에 적용한다.

정상 분석 호출 수는 N+M, 0≤M≤N≤5다. 세 번째 분석, 자동 재시도, 별도 조정 AI,
초안 작성·재작성·출력 다듬기와 기억 쓰기 AI는 추가하지 않는다. Critic 저장과
기존 출력/리롤/삭제 동작은 그대로 기존 소유자를 따른다.

## 프롬프트·검색·추천 계약

`prepare_turn_multi_agent.go`의 공통 지침과 5개 실제 기본 프롬프트가 실행 기본값이다.
test.5부터 공통 지침도 편집·저장·복원할 수 있다. 사용자 공통 지침은 번들 공통 지침을
대체하며, 각 호출은 선택한 공통 지침 + 해당 담당 지침 + 기존 단계별 과제로 조립한다.
1차와 보충 분석은 같은 요청에서 읽은 설정을 사용한다.
test.7은 다섯 기본 역할 지침을 장면 판단·근거 구분·추가 검색·담당 간 요청·보충 추천으로
구체화했다. 사건은 인과/시점, 객관 상태는 지속/임시 상태와 변화, 주관 기억은 지식 경로와
관계 방향/비밀, 세계는 규칙 범위와 물건의 상태, 목표는 약속의 진행/완료/불확실성을 다룬다.
기존 사용자 수정본과 공통 지침은 덮어쓰지 않는다. 빈 역할 수정본은 새 기본본을 사용하고,
사용자 수정본에서 새 기본본으로 바꾸려면 해당 담당의 기본값 복원 후 저장을 사용한다.
`memory_preprocessing.v1`에는 담당, 원문 후보, 별도 턴 요약, 현재 입력, 최근 대화,
보호 지침, 입력/선정 예산이 있다. 응답은 `selected_ids`, `selected_summary_ids`,
`reasons`, `search_requests`, `related_requests`, `unresolved`를 사용한다.
사건 담당의 턴 요약과 사실은 기존처럼 독립 K이고 각 배열 내부의 순서를 보존한다.

담당별 후보 원문 입력 기본 한도는 32,000자이며 설정할 수 있다. 완전한 원문 단위로
입력하고 미포함 수를 표시한다. 검색은 담당당 최대 1개다. 일반 누락 질문을 먼저
처리하고 다른 담당 질문은 이어서 같은 한도 안에서 처리한다. 추가 질문은 원문과
`search_limit`/`round_limit` 사유를 남긴다. 임의 SQL, 파일, 웹 검색은 제공하지 않는다.
다른 담당에게는 공개 정본 참조만 전달하며 자유 서술 형태의 비밀 추론을 복제하지 않는다.
해당 질문은 Go 검색에 사용하고, 각 담당은 자신의 범위에 맞는 정본 후보를 다시 받는다.

기존 K·담당별 글자 예산·전체 주입 예산을 **호출 전에** 알린다. 추천을 받은 뒤
Go가 점수나 K를 다시 적용해 추천을 버리지 않는다. 모델이 선언된 한도를 초과해도
정본 추천을 유지하고 `budget_overrun_chars` 및 담당 결과로 초과를 관찰한다.
이는 활성 AI 추천에 대한 명시적 보존 방식이다. OFF의 기존 제한은 바꾸지 않는다.

추천이 비었거나 호출 실패로 추천을 받지 못한 담당에는 그 요청에서 계산한 기존 Go
선정 결과를 쓴다. 다른 AI의 초과 추천이 이 기본 기억을 밀어내지 않도록 기존 선정 ID를
보존한다. 보충 호출이 실패하면 첫 추천을 유지한다. 정상 보충 응답이 빈 추천이면 Go로
돌아간다. 일부 JSON이 손상돼도 앞서 받은 ID는 보존하며 파싱 실패와 원문을 함께 남긴다.
존재하지 않는 정본 ID를 사실로 만들지 않는다. `canonical_reference_unresolved`로
노출하며 이를 핑계로 받은 추천을 지우고 Go 추천을 대신 넣지 않는다.

## 설정과 사용자 화면

추가 기능 → 전처리 다중 에이전트에서 전체/담당별 사용, 별도 제공자·주소·모델·키,
온도·출력 길이·시간·추론 설정, 공통 및 담당 프롬프트를 편집한다. 새 담당 설정은
개별 AI 연결이 기본이다. 출판사 연결 공유는 선택 사항이며 이미 저장된 공유 선택은
유지한다. 연결을 공유해도 각 담당의 전용 프롬프트를 사용한다.
기본 프롬프트 복원과 실제 요청의 입력·적용 프롬프트·원문 결과·선정 출처를 확인한다.
JavaScript는 화면과 HTTP 전달만 담당한다. 설정 저장/화면 열기만으로 AI를 호출하지 않는다.

test.6에서는 일반 설정과 같은 제공자 목록을 선택식으로 제공하고, 지원 제공자의 Flex
옵션을 표시한다. 개별 연결은 담당별 처리 모드, 공유 연결은 출판사 처리 모드를 따른다.
OpenAI 호환 서비스의 `service_tier`, AI Studio의 `serviceTier`, Vertex Flex 헤더를
기존 Go 제공자 전송 경로에서 적용한다. Claude 직접 연결에는 Flex를 표시하지 않는다.
제공자를 바꿔 숨겨진 옵션은 보존하되 새 제공자에 맞지 않는 개별 서비스 티어를 보내지 않는다.
모델별 지원 가능 여부를 자동 조회하거나 모든 모델의 Flex 성공을 보장하지 않는다.

온도와 최대 출력 토큰은 접힌 세부 설정에서 AI 연결 바로 아래로 옮겼다. 두 값은 기존
담당별 설정을 사용하며 출판사 연결 공유 중에도 각 담당의 1차·보충 호출에 적용한다.
대기 한도와 추론 설정은 세부 설정에서 조절한다. 상세 시험은
[test.6 기록](archive-center-4.3-test-build-6.md)을 따른다.

`GET/PUT /config/memory-preprocessing`가 백엔드 전체 설정을 관리한다. 사용자 편집은
`ARCHIVE_CENTER_DATA_DIR/memory-preprocessing.json`에 파일 교체 방식으로 저장하고,
번들 기본 프롬프트는 Go에 포함한다. Windows 실행기는 기존 안정 데이터 경로를 사용하고,
POSIX 실행기도 실제 DATA_ROOT를 같은 환경 변수로 전달한다. 직접 실행에서 환경 변수가
없으면 OS 사용자 설정 디렉터리의 `ArchiveCenter/data`를 사용한다. 설치 파일·프롬프트
폴더 덮어쓰기로 사용자 편집을 지우지 않는다. test.7부터 API 응답은 저장된 키를
비밀번호 입력칸에 다시 채울 수 있도록 반환하며 응답 캐시를 금지한다. 삭제 체크박스는
제거했다. 키 값을 보내면 수정하고, 빈 문자열을 명시적으로 저장하면 키를 비운다.
키 필드 자체가 생략된 요청은 기존 키를 유지한다. 키는 이 데이터 파일에 저장되므로
패키지/공유용 파일에 포함하지 않는다.

`settings.shared_prompt`는 저장된 공통 수정본이며 빈 문자열은 번들 기본값 사용이다.
응답의 `shared_prompt`는 실제 사용할 본문, `default_shared_prompt`는 복원할 기본본이다.
구형 UI가 PUT에서 해당 필드를 생략하면 기존 수정본을 유지한다. UI의 기본값 복원은
편집칸에 반영하고 저장할 때 적용한다. 저장 실패 시 편집값을 보존하고 실패를 표시한다.
Endpoint 라벨과 저장 키 표시·편집, 새 역할 기본본의 전달 검증 및 패키지는
[test.7 기록](archive-center-4.3-test-build-7.md)을 따른다.

## 검증 범위와 남은 확인

test.12는 1차 뒤 담당별 추가 검색을 병렬화한다. 임베딩·검색은 동시에 진행하며,
기존 공유 요청 입력을 쓰는 원문 연결·조립은 요청 내부에서 순서대로 수행한다.
모든 결과는 담당 순서대로 병합한 뒤 2차에 공급한다. 검색/AI 호출 횟수·정본 범위·
받은 추천의 순서와 원문은 유지한다. 이미 조립한 후보는 렌더링 전의 요청 내부
사본을 재사용하며, 공개 진단문에서 비공개 기억을 복원하거나 영구 캐시를 만들지 않는다.

HUD는 추가 검색의 실제 경과 시간과 완료 수를 표시하고, 접힌 세부 보기에서 검색별
서버 확인·임베딩·벡터 검색·유효성 확인·원문 연결·조립 대기·후보 조립 시간을 제공한다.
동시에 실행된 검색별 시간은 합산하지 않는다. 기존 백엔드 시간의 전처리 검색 단계는
이 전체 경과 시간을 사용하며 입력 조립 시간 안에 포함된다.
실제 요청 경로의 동시 검색·정본 주입 및 JavaScript 실행형 시험과 남은 실제 환경
검증은 [test.12 기록](archive-center-4.3-test-build-12.md)을 따른다.
기존 예제의 전처리 구조·기본 호출 수·차이는 [비교 기록](archive-center-4.3-preprocessing-comparison.md)에 정리했다.

test.8은 기존 HUD에 전처리 담당별 1차·보충 호출 시간과 합계를 추가한다.
전처리를 사용한 담당만 나타나며, 실행 중 경과 시간과 실패한 호출도 표시한다.
응답 수신 후에는 준비 시작부터 응답까지의 총시간과 본문 응답 대기 시간을 고정하여
표시한다. 다음 입력 시 저장 모드에서도 현재 생성 카드의 시간을 확인할 수 있으며,
실제 저장 시점은 바꾸지 않는다. [test.8 기록](archive-center-4.3-test-build-8.md) 참조.

`prepare_turn_multi_agent_test.go`는 실제 제공자 HTTP 경계만 대역으로 사용한다.
Go 병렬 실행, 검색/보충 횟수, 실패 시 첫 결과, OFF 무호출, 낮은 순위·분량 초과 추천의
실제 선정/순서 보존, Go 기본 선정 유지, 부분 JSON, 저장/재시작/키 비노출을 시험한다.
실제 `/prepare-turn` 테스트는 정본 후보 → 추천 → 최종 주입문 → payload 적용 계획 →
출판사 support packet까지 연결하며 Go가 다른 사건을 다시 추가하지 않는지도 검사한다.

[test.5 기록](archive-center-4.3-test-build-5.md)은 서로 다른 5개 HTTP 연결·모델·키와
두 분석 단계의 실제 전송 프롬프트, 공통 수정본의 저장/재로드/복원, 선택적 출판사 연결
공유 및 로컬 브라우저 편집·저장·반응형 화면 검증을 추가한다. test.5는 새 패키지만
생성하며 기존 설치 폴더 교체, 백엔드 기동, RisuAI 설치는 수행하지 않는다.

패키지 빌드 및 로컬 실행은 [test.2 기록](archive-center-4.3-test-build-2.md)을 따른다.
기존 폴더 교체 후 버전·실제 DB/Chroma 준비 상태·전처리 API를 확인했다. 실제 RisuAI 화면에서 설정을
저장하고 유료 제공자로 5개/보충 호출, 비용·지연, 비밀 공개 범위, 최종 표시 결과를
확인하는 단계는 아직 별도 확인이 필요하다. HTTP 대역 시험은 실제 제공자의 품질이나
모든 OS의 실행 증거가 아니다. 4.3 전체 공개 릴리스 완료를 의미하지 않는다.
