# Archive Center 4.3.0-test.10 — 전처리와 사용자 중심 이야기 지원

날짜: 2026-09-07. 상태: `implemented_unverified`.
소스·실행형 회귀·패키지 검증과 실제 RisuAI/모델의 출력 품질을 구분한다.

## 사용자 확정 방향

이야기는 사용자가 결정한다. Archive Center는 기억과 선택적 아이디어를 제공하며,
어떤 전개가 허용되는지 정하거나 특정 결과를 요구하는 역할을 맡지 않는다.
금지 지침을 긍정적인 표현으로 포장하는 방식도 사용하지 않는다.
사용자가 원하면 설정·시간·인물·관계·사건을 변경할 수 있고 과거 기억은 그 선택을
이해하는 참고자료다. 기존 단일 Publisher와 다섯 전처리 담당을 사용하며 별도의
초안 작성·출력 재작성·후처리 AI 호출은 추가하지 않는다.

## 수정 내용

- Publisher 기본 프롬프트는 `current_arc`, `narrative_goal`, `next_beats`,
  `pressure_level` 네 가지 제안을 요청한다. 금지 행동·필수 결과·장면 명령은
  기본 생성 요청에서 제외한다. 실제 모델 입력의 실행 지시와 세 가지 렌더 형식도
  선택적 아이디어임을 명시한다. 이전 응답 형식의 parser 호환은 유지한다.
- 전처리 공통 및 다섯 역할 기본 프롬프트는 사용자 의도를 돕는 기억 준비에 집중한다.
  과거 계획을 최근 완료 기록과 함께 읽도록 하고 사용자의 명시적 변경을 존중한다.
- 사건 사실이 입력 한도를 모두 소모하여 턴 요약을 못 보던 구성을 수정한다.
  사실·요약에 입력 공간을 나누고 남는 공간은 공유한다. 상한은 기존과 같이 후보
  본문의 문자 수이며 전체 직렬화 요청이나 과금 토큰 수의 상한은 아니다.
- 요청 안에서 안정적인 F/S/L 선택 번호를 제공하고 정확한 원래 ID에 연결한다.
  전체 ID 응답도 유지한다. 잘못된 ID를 비슷한 기억으로 추측하여 치환하지 않는다.
- 공개 `general` 근거의 역할 간 참조 표현을 맞춘다. 기존 개인 소유·열람 대상·
  주관 기억의 공유 범위는 유지한다. 선택 사실에는 알려진 출처 턴을 표시한다.
- 세계 담당이 기존 범위의 로어북 후보를 함께 검토한다. 명시적 빈 로어 선택은
  이번 AC 추가 주입 없음, 미평가/실패는 기존 Go 또는 앞선 성공 선택 유지다.
  원문·선택 순서·동일 내용 병합의 첫 출처를 유지한다. RisuAI가 직접 넣은 내용은
  그대로 두며, 중복 주입과 AI 미선택은 기존 최종 예산 진단에 표시한다.
- Chroma의 정상 응답을 1 MiB에서 잘라 JSON 오류로 만들던 결함을 수정한다.
  오류 HTTP 응답의 기존 크기 제한은 유지한다. 검색 결과 수나 범위는 줄이지 않는다.
- 추가 검색의 실제 오류와 부분 성공, 목표 후보의 원본/관련성 처리 건수,
  누락된 연결 설정 항목, 실제 외부 요청 전 로컬 실패를 구분해 기록한다.
- HUD에 기존 백엔드 단계 시간을 표시한다. 보완 검색은 기억 조립에, 출판사 호출은
  응답 조립에 포함되므로 이 값을 합쳐 전체 시간으로 계산하지 않는다.
- 최종 입력 화면은 백엔드 미리보기와 요청 직전 관측을 구분한다. 사용자 원문 확인과
  보조블록 확인의 불일치 이유를 나누고 이전 표시 결과가 새 미리보기로 넘어가지 않게 한다.
  출력·저장·리롤을 더 어렵게 하는 조건은 추가하지 않는다.

## 검증과 남은 확인

- 실제 생산 함수를 사용하는 전처리 HTTP 경계 회귀: 병렬 호출, 두 차수,
  요약 공급, 참조 번호, 원문/순서, 공유 범위, 빈 선택과 실패 보존, 설정 보존.
- 전체 `/prepare-turn` → 세계 담당 HTTP 응답 → 로어북 원문 → 최종 payload/예산
  경로에서 선택 항목과 명시적 빈 선택을 확인한다. 운영 데이터를 변경하지 않는다.
- 2,643,826바이트의 Chroma 정상 응답은 수정 전 JSON 오류를 재현했고 수정 후
  128개 후보와 전체 임베딩이 복원됐다. 오류 응답 크기 제한 회귀도 포함한다.
- Publisher 실제 요청 조립 → HTTP 대역 → 세 가지 가이드 렌더 → payload를 확인한다.
  프롬프트의 사용자 결정권과 제안 성격, 출처 시점 보존을 검사한다.
- Host 실행형 회귀는 요청별 시간 보존, 중복/다른 요청 분리, 관측/미관측/불일치
  표시를 확인한다. 로컬 HTML 시각 확인은 브라우저 URL 보안 정책으로 차단됐다.
- 전체 Go 검사 `go test ./... -count=1`, 변경한 HTTP/vector 영역의 `go vet`,
  `node --check "Archive Center.js"`, `git diff --check`를 통과했다.
  이 검사는 사용자 운영 서비스나 실제 제공자를 호출한 증거가 아니다.
- 이번 작업 시작 시점과 비교한 JavaScript 변경은 추가 116줄/삭제 19줄이다.
  이전부터 있던 작업 내용은 유지했다.

test8의 실제 payload 불일치 원인은 원래 관측/hash 자료가 없어 확정하지 못했다.
Chroma 결함이 그때의 정밀 검색 오류와 동일 원인인지도 확인되지 않았다.
목표 후보 0건의 원본 읽기·필터 원인은 첨부에 없으므로 새 진단으로 다음 실행에서
확인해야 한다. 이 PC의 현재 저장 설정에는 세계/목표 담당의 연결값이 모두 있으나,
실제 제공자의 모델 이용 가능성과 실행 중인 백엔드 적용은 검사하지 않았다.

실제 이야기의 능동성·사실 일치·비밀 유지·사용자 의도 반영은 새 빌드를 사용한
출력으로 확인해야 한다. 회귀나 패키지 성공을 실제 글쓰기 개선으로 대신하지 않는다.

## 적용 범위와 패키지

테스트 패키지는 새 폴더에 생성한다. 기존 백엔드·설치 폴더·DB·RisuAI는 교체하거나
실행하지 않는다. 사용자가 백엔드 실행과 플러그인 적용을 맡는다.
저장된 사용자 수정 프롬프트는 보존한다. 수정본을 사용 중이면 기본 복원 후 저장할 때
새 기본 전처리 프롬프트가 적용된다. Publisher 파일 수정본도 임의 덮어쓰지 않는다.

검증 로그와 변경 전 기준: 작업 루트 `.tmp-feedback-43/test10-*`.
