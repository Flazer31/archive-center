플러그인과 새로 컴파일한 Go 백엔드를 함께 적용한다. 기존 설치를 바꿀 때에는 사용 중인
백엔드를 종료하고 설정·데이터를 유지하는 기존 적용 절차를 따른다. 새 패키지의 01 파일로

기존 test.20과 설정·DB·챗은 보존했다. GitHub 공개 릴리스는 4.2.0을 유지한다.

## 한 묶음으로 수정한 네 경로

1. **기본 기억 전달 폭**: `분류별 핵심 기억 우선 수`만큼 각 분류의 후보를 먼저 고려하고,
   남은 기존 문자 예산에 점수순으로 세부사항을 담는다. 개수만으로 남은 기억을 제외하지
   않는다. 검색 수는 별도 설정이다. 문자 예산·분류별 사용자 예산은 그대로 적용한다.
2. **일반 주관 기억**: 이미 보유자 범위가 확인된 `subjective_memory`는 정상적인 주관
   기억 후보로 전달한다. 보유자·원래 관점·출처 단위·출처 턴을 함께 보낸다. 실제 보호 대상
   지식의 안내 경로는 유지하며, 다른 보유자의 비공개 기억이 일반 공개로 바뀌지 않는다.
3. **현재 값 판정**: 같은 현재 필드의 후보가 경쟁하면 출처 턴을 먼저 비교한다. 과거 값의
   단어가 질문에 있어도 높은 관련성 점수만으로 최신 출처를 대체하지 않는다. 검색 점수는
   최종 전달 우선순위를 정한다. 서로 다른 과거 사건을 최신 사건 하나로 합치지 않는다.
4. **전처리 보완 검색**: 현재 필드의 그룹 키와 증거 참조를 분리했다. 같은 필드라도 출처·
   시점·값이 달라진 후보는 다른 참조로 2차 입력에 도달한다. 기존 추천과 참조는 유지해
   보완 호출 실패 시 1차 선택을 보존한다. 정상적인 최종 빈 추천은 기존 Go 선정을 사용한다.

전처리 OFF·AI 추천·추천 없음·부분 실패는 같은 조립 순서를 사용한다. AI가 선택한 분류는
원문과 순서를 유지하고, 추천이 없는 분류만 미리 계산한 Go 선택을 가져온다. AI가 이미
선택한 결과를 뒤에서 다시 자르지 않는다. 예산은 선택 전에 전달한다.

기존 `core_objective_memory_max_items` 정수 저장 키는 유지하므로 설정 이전은 필요 없다.
진단 계약 `core_priority_memory_delivery.v4`와 `core_priority_target`가 변경된 의미를 나타낸다.
AI 입력의 `max_items_per_group`는 null, `core_priority_target_per_group`는 기존 설정값이다.
기본 프롬프트의 예산 설명도 맞췄으며 저장된 사용자 프롬프트는 덮어쓰지 않았다.

## 검증

- 새 네 묶음 회귀가 수정 전 소스에서 실패한 것을 기록한 후 수정했다. 충분한 공간의 세부
  기억, 96개 주관 기억과 다섯 분류의 경합, 다른 보유자 비밀, 출처 40/113턴, 옛 단어를
  포함한 현재 상태 질문, 새 출처의 실제 2차 모델 입력과 2차 실패 보존을 검사했다.
- 전체 Go **35개 패키지, 일반 시험 3,855개와 하위 시험 788개 통과**, 실패 0개.
  MariaDB 8개·Chroma 2개·실제 제공자 1개·POSIX 실행 비트 1개는 환경상 생략했고,
  별도 두 도구 패키지는 시험 파일이 없다. 활성/패키지 JS 구문 검사도 통과했다.
- 첫 전체 실행에서 이전의 하드 개수 제한을 기대한 시험과, Go 복원 조립 순서 차이가
  검출됐다. 개수 제한 시험은 추가 내용의 보존과 우선순위 검증으로 변경했고, 복원 순서의
  차이는 기존 조립 소유자에서 수정했다. 후보 풀 보존 시험을 약화하지 않고 통과했다.

### 보내준 test.20 내용으로 고정 비교

수집한 후보와 OFF의 직접 근거를 결합한 원인 분리 시험이다. 빠진 메타데이터에는 중립

`prepare_turn_priority_memory.go`, `prepare_turn_multi_agent.go`와 관련 회귀를 변경했다.
