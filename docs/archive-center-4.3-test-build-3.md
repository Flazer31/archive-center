# Archive Center 4.3.0-test.3

2026-09-06 로컬 테스트 빌드. 공개 GitHub 릴리스가 아니다.

## 원인과 수정

- UI에는 `http://100.96.60.55:28080`이 저장되어 있었지만 직전 재시작은
  `127.0.0.1:28080`에서만 접속을 받았다. UI가 저장 주소를 무시한 문제가 아니라
  백엔드 실행 주소를 좁힌 작업 때문에 기존 접속이 끊긴 것이다.
- 사용자가 기존 Tailscale 주소로 재실행을 명시적으로 승인했다. 같은 관리 실행기와
  기존 데이터로 `100.96.60.55:28080` 접속을 복구했으며 UI의 주소는 수정하지 않았다.
- `renderSettingsPanel()`이 상태 응답을 기다린 뒤 창을 열던 순서를 수정했다.
  입력창과 이벤트를 먼저 표시하고 Go 상태 응답은 상태 영역에만 반영한다.
  이전 화면의 응답은 기존 화면 요청 번호로 구분하며, 편집 중인 값을 다시 쓰지 않는다.
- 뒤늦게 생기는 상태 영역의 큐 비우기 버튼은 기존 영역에 위임한 클릭 처리를 사용한다.
- 전처리 설정 조회 실패 시 설정의 Backend URL과 서버 실행 상태를 확인하도록 안내한다.
- 저장된 `settings.bridgeUrl`을 쓰는 기존 통신 경로를 유지한다. 로컬 주소, LAN,
  Tailscale, 도메인 중 특정 주소로 자동 대체하지 않는다. 서버가 접속을 받는 주소는
  실행기 설정이며 클라이언트가 저장한 접속 URL과 구분한다.
