# Archive Center 4.3.0-test.8 — HUD 시간 표시

날짜: 2026-09-07. 상태: 구현 및 소스·시험 대역 검증, 설치된 RisuAI 확인 대기.

## 동작

- 전처리가 실행된 턴에만 담당별 시간 영역을 표시한다. 켜진 담당의 1차·보충 호출을
  구분하며 실행 중 경과 시간, 완료/실패 여부와 담당별 호출 합계를 표시한다.
- 담당별 합계는 그 담당의 AI 호출 시간이다. 다른 담당과 병렬로 실행되므로
  담당별 시간을 모두 더한 값이 전체 대기시간은 아니다. 보완 검색 대기는 별도이며
  아래 응답까지의 총시간에 포함된다.
- 응답 수신 후 **준비 시작 → 응답**, **본문 응답 대기** 시간을 HUD에 남긴다.
  전자는 해당 요청의 HUD를 처음 띄운 시점부터, 후자는 첫 beforeRequest 반환부터
  accepted afterRequest에서 관측한 응답 수신 시점까지다. 모두 Host 시계를 사용하며
  네트워크·제공자 재시도 대기를 포함한다. 첫 토큰 시간이나 순수 모델 연산 시간은 아니다.
- 총시간은 응답 시점에 고정된다. 이후 평론가·저장이나 다음 사용자 입력 대기는
  포함하지 않는다. 다음 입력 시 저장 모드에서도 현재 생성 카드를 닫기 전까지
  시간을 확인할 수 있다. 다음 요청에는 이전 시간/전처리 행이 남지 않는다.

## 소유권과 범위

Go의 실제 전처리 호출이 기존 요청별 HUD ledger에 시작·종료 시간을 기록한다.
`turn_workflow_hud.v3`에 선택적 `preprocessing` 배열을 추가했으며 기존 12단계,
이벤트 스트림, 기억 선정, 호출 횟수 및 fallback은 유지한다. 설정 OFF일 때 생략한다.
키·프롬프트·기억 내용은 HUD 시간 자료에 포함하지 않는다.

JS는 이 ViewModel을 표시하고, 기존 HUD 타이머로 실행 중 시간을 갱신한다.
`host_timing`과 `host_generation_finished`는 해당 HUD의 임시 관측/표시값이다.
백엔드의 최종 출력 수락·저장·복구 판단에 사용하지 않는다.

## 검증

- Go 실제 전처리 실행 + HTTP 제공자 대역: 병렬 실행 중 running 관측, 5개 담당 순서,
  보충/실패 포함 시간과 원래 호출 trace의 일치, 담당별 합계, OFF 생략, snapshot 격리.
- JS 실제 함수 실행: OFF 표시 없음, 두 동시 경과시계, 호출 실패/보충 시간,
  응답 시간 고정, 동일 요청 재시도 시 최초 시작 유지, 다른 요청 혼입 방지,
  다음 입력 시 저장 모드의 시간 카드 유지 및 backend 상태 불변.
- 전체 Go 패키지 시험 실행에서 버전 문자열 기대값 한 건을 수정했다. 수정 후
  JS 회귀 패키지가 통과했고 나머지 Go 패키지는 전체 실행에서 통과했다.
  `go vet ./internal/httpapi`, JavaScript 구문 및 diff 검사도 통과했다.
- 실제 시간 표시 함수를 사용한 로컬 브라우저 화면을 1600/390px에서 검사했다.
  시험 대역 화면이며 설치된 RisuAI·실제 계정 호출에 대한 증거는 아니다.

검증 자료: 작업 루트 `.tmp-feedback-43/hud-test8*`.
실제 모델 답변의 기억 활용 품질, 기존 test.6의 호출 설정/정밀 검색/로어북 문제는
이번 HUD 변경의 해결 범위에 포함되지 않는다.
