# Archive Center 4.3.1-test.2 — 기본 기억 회수 복원

2026-09-10 로컬 Windows 시험 패키지. 소스와 패키지 검증을 마쳤으며 실제 RisuAI 회상 품질은
`implemented_unverified`다. GitHub 업로드·태그·공개 릴리스·사용자 백엔드 시작/종료는 하지 않았다.

## 바로 사용하기

1. 기존 Archive Center 백엔드를 평소 방법으로 종료한다.
2. 아래 새 폴더의 `01_start_archive_center_windows.bat`를 실행한다.
3. 같은 폴더의 `Archive Center.js`로 RisuAI의 플러그인을 교체한다.
4. 플러그인과 백엔드 표시가 `4.3.1-test.2`인지 확인한다. 기존 백엔드 주소·키·프롬프트는 유지한다.

기본 기억 수정이므로 전처리·출판사를 꺼도 적용된다. 이미 저장한 기억을 사용하며,
이 빌드 확인만을 위해 콜드스타트나 기억 삭제를 먼저 할 필요는 없다.
한 사례를 확인한다면 기억에 저장되어 있는 습관·약속의 단서를 입력하고 편집 확인의 실제 주입 내용을 비교한다.
본문 AI의 회상과 주입 성공은 구분한다. 과거 벡터가 오래된 경우나 공개 사실 자체가 추출되지 않았던
혼합 요약까지 이 변경으로 모두 복원되는 것은 아니다.

## 파일과 식별

- 폴더: `source/_dist/4.3.1-test.2/Archive Center 4.3.1-test.2 Windows Test`
- ZIP: 같은 위치의 `Archive Center 4.3.1-test.2 Windows Test.zip`
- ZIP 크기: **18,101,313 bytes**
- ZIP SHA-256: `6572ed275977a59118ed9e528f63f5be3208174b8e3bfc222f82fab2288d898f`
- Go 백엔드 SHA-256: `2895eb46bae3f5d666391908d20340e0a96268440b4484fd130f9fd5ebfdf420`
- JS SHA-256: `1edf35d0ebe39ec27719bc813d2eda692fc057d694e118595e6ddd62f6a3d022`

  `AC_BUILD_VERSION`을 `4.3.1-test.2`로 맞췄다. 백엔드 바이너리도 test.1과 다른 새 파일이다.

## 반영 범위

[다섯 항목의 구현 기록](archive-center-memory-recall-restoration-plan.md)을 따른다.

- 질문별 검색 결과와 관련성 근거를 보존하고 합친 결과의 같은 K 재절단 제거.
- 표시 요약으로 좁히기 전에 사실 후보 구성. 같은 요약에 가려진 서로 다른 세부 사실 보존.
- 한국어 조사와 원래 입력의 독립적인 어휘 단서 회수.
- `prune_targets`의 JSON 문자열 일치로 요약 전체 중요도를 낮추는 동작 제거. 힌트 기록 유지.
- 공개 직접 근거의 검색 투영과 Go/전처리의 초기·보완 후보 경로 통일.
- 본문 Top K UI 제거, Go 문자 예산에 따른 조회량 사용. 분류별 핵심 우선 수와 최종 문자 예산 유지.
- 정상 AI 추천/순서, 추천 없음·일부 실패의 Go 선정, 보완 실패 시 1차 결과 유지.
- 앞선 test.1의 `06_change_chromadb_port_windows.bat`와 기존 설치/실행 파일 포함.

프롬프트, 추가 AI 호출, 저장 스키마, 분기·리롤·저장 확정 계약은 바꾸지 않았다.
JavaScript 변경은 **+1/-9**이며 후보 계산은 Go에서 수행한다.

과거에 이미 감소한 중요도, 운영 벡터, 요약 원본을 추정해서 일괄 수정하지 않았다.
