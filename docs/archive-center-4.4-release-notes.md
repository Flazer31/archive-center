# Archive Center 4.4.0

4.3.1의 기억 회수 폭을 유지하면서 전처리와 후보 조립의 반복 비용을 줄이고, 자동 기억 예산·턴 처리·오류 진단을 보완했습니다.

- **반복 후보 조립 개선:** 같은 요청에서 자료 해석과 기본 비교를 재사용합니다. 추가 질문마다 전체 기억을 다시 조립하지 않으며 질문별 검색 근거·출처·AI 추천 순서는 유지합니다.
- **전처리 묶음 호출:** 제공자·모델·실제 호출 설정이 같은 담당은 하나의 요청으로 묶습니다. 담당별 결과와 일부 실패 시 Go 기본 선정은 구분하며, 다른 담당의 모델 설정을 가져오는 기능을 제공합니다.
- **입력 중복과 사용량:** 공통 입력과 근거의 중복 전송을 줄이고 요청별 사용 토큰·추론 토큰·시간을 확인할 수 있게 했습니다. 실제 사용량은 제공자가 반환한 정보에 따라 표시합니다.
- **자동 기억 예산:** 직접 근거가 일반 기억 공간을 먼저 독점하지 않도록 종류별 초기 공간을 배분하고, 남는 예산을 재사용합니다. 전처리를 끈 기본 기억에도 적용합니다.
- **턴·HUD:** 여러 사용자 입력, 리롤·삭제 이후 턴 인식과 중단 표시를 보완했습니다. HUD는 담당 5명의 1차·2차 시간표를 유지하며 버전을 일치시켰습니다.
- **모델 설정:** 전처리에도 제공자·모델별 추론 설정을 적용하고 설정 조회·저장 경로를 정리했습니다.
- **오류 확인:** 백엔드·제공자·설치/실행 실패의 진단 기록과 오류 보고 내보내기를 추가했습니다. Windows PowerShell 5.1에서 한글 데이터 경로를 읽는 문제도 수정했습니다.
- **원작 자료:** 의미 없는 기호·조사·광고 문구 등 자료 수집 잡음의 유입을 줄였습니다.

## 설치와 업데이트

기존 관리형 설치는 Archive Center UI의 업데이트 확인·적용을 사용합니다. 개인 DB·API 키·설정은 배포 관리 파일에서 제외합니다.
**RisuAI에 등록한 플러그인도 별도 업데이트하거나 새 `Archive Center.js`를 가져와 4.4.0으로 맞춰주세요.**

신규 Windows 사용자는 ZIP을 풀고 `01_start_archive_center_windows.bat`를 실행하거나 PowerShell에서 다음 명령을 실행합니다.

```powershell
irm https://raw.githubusercontent.com/Flazer31/archive-center/main/install-windows.ps1 | iex
```

Linux / macOS / Termux:

```sh
curl -fsSL https://raw.githubusercontent.com/Flazer31/archive-center/main/install.sh | sh
```

명령 하나로 설치와 백엔드 실행을 이어서 진행합니다. RisuAI 플러그인 등록과 백엔드 주소 설정은 별도입니다.
기존 설치에는 신규 설치 명령 대신 UI 업데이트를 사용합니다.

배포 파일은 Windows x64 설치·업데이트, Linux x64·arm64, macOS Intel·Apple Silicon, Termux arm64의 ZIP 7개와 SHA-256 체크섬입니다.

## 확인 범위

실사용 관측에서 추가 기억 검색은 1.499/1.454초였으며, 모델 호출이 120초 후 실패하면 그 대기는 남습니다.
모든 환경의 시간·RAM 사용량 감소를 보장하는 수치는 아닙니다. 기억 후보를 줄여 얻은 성능 개선으로 처리하지 않았습니다.
완료된 약속의 상태 이력, 맥락 묶음과 장면 시점의 구조적 개선은 4.5·4.6 후속 범위입니다.
