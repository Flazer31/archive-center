## 1. 이번에 확정한 진행 방향

- **4.4:** test.17까지의 수정과 영향 범위 검증을 마무리한다. 큰 폭의 D 의미 중복 통합은
  보류하며 4.4 완료의 필수 조건에서 제외한다. 해당 기능을 구현 완료로 처리하거나
  다른 버전에 자동 이관하지 않는다.
- **지금 할 상태 작업:** 설계 원칙과 비교 사례를 고정한다. 개별 약속 문구·인물·턴에 맞춘
  임시 보정을 반복하지 않는다. 정상 저장된 완료 정보가 전달 중 사라지는 등 별개의
  결함이 재현되면 그 범위에서 수정할 수 있다.
- **4.5:** 기존 출처를 유지하면서 관련 내용을 함께 이해할 수 있는 전달 단위를 만든다.
  보류한 D의 대표 사실 통합을 선행 조건으로 삼지 않는다.
- **4.6:** 약속·상태의 진행 이력, 항목별 유효 시점, 기존 자료 복원을 핵심으로 구현한다.
  기본 상태 관리와 시간 전달을 먼저 검증한 뒤 선택형 신체 상태 기능을 진행한다.
- **4.7 이후:** 기존 버전 순서를 유지한다. 새 연상 엔진·전체 그래프·후처리 구현을 4.4에
  끌어오지 않는다. 현재 기본 기억의 문제를 선택형 전처리 사용으로만 해결하도록 만들지 않는다.

## 3. test.16 사용자 자료에서 확인한 결과

근거: 사용자가 test.16 결과로 제공한 최종 입력 첨부

사용자 세션 원문을 이 문서에 복제하지 않고 수치와 판단 범위만 기록한다.

전체 일반 기억은 조립 비용을 포함해 16,000/16,000자다. 직접 근거는 약 19.3%이며,

이것을 전체 기억 정확도나 전처리 토큰 절감률로 해석하지 않는다.

보조 입력은 '요청 반영 확인'으로 표시됐다. `effective_user_text_not_observed`는 같은
관측에서 사용자 입력문 일치가 확인되지 않았다는 뜻이다. 보조 입력 실패로 바꿔 읽지 않으며,
이후 다른 플러그인 처리와 제공자에게 전송된 최종 요청 전체도 확인한 것으로 취급하지 않는다.
로어북 17개는 `lorebook_already_present_in_payload`로 추가 삽입이 생략됐다.
전처리 역할별 입력·응답·usage, 이번 사용자 입력 원문과 본문 출력은 이 첨부에 없으므로
ON/OFF 설정별 품질, 실제 비용·시간, 출판사 방향과 사용자 의도의 일치는 이 자료로 확정하지 않는다.

### 2026-09-14 추가 재현 — 배정은 4.5·4.6 유지

[상태·전달 경계 재현](../../_diagnostics/20260914-state-boundary-recheck/README.md)은 활성 Go 함수를
기존 recording store와 함께 실행한 오프라인 관측이다. 사용자 DB나 실제 평론가 재호출 검증이 아니다.

| 실제 함수에 준 조건 | 관측한 문제 또는 정상 대조 | 배정 |
| --- | --- | --- |

기존 완료 테스트는 정확한 식별자·정상 추출을 받은 경로를 검증했다. 여러 표현의 동기화와

문제 발생 구조의 재현과 제안한 설계의 해결 검증도 구분한다. 이번 문서로 구현을 시작하지 않는다.

## 6. 4.5 — 출처와 맥락을 함께 전달

기존 기억과 검색 후보를 유지하면서 하나의 기록에 속하는 주체, 행위, 조건/범위,
인용 근거를 함께 이해할 수 있는 문장으로 구성한다. 같은 규칙의 주소·본문·근거가 각각
예산을 받아 단독 전달되는 사례를 우선 비교한다. 원문 화자를 알 수 없으면 임의로 부여하지 않는다.

구성 출처와 개별 사실을 보존하고, 같은 문자 예산에서 세부사항과 부정·조건이 유지되는지
검증한다. 정상 AI 추천의 내용·순서를 조용히 교체하지 않으며, 새 문장을 만들었다는 이유로
저장 원문을 합치거나 삭제하지 않는다. 이 버전은 4.6의 상태 전환 판정을 대신하지 않는다.

추가 확정 방향: 검색용 field와 본문 전달 단위를 분리한다. 규칙·대상·적용 범위·근거는
출처 대응을 유지한 채 함께 읽을 수 있게 구성하고, 같은 기록의 요약/세부 표현을 반복해서
보내는 경우를 실제 전달량으로 비교한다. 동일 source라는 이유만으로 모든 문장을 합치거나
검수 수량을 배포 수량으로 옮기는 등의 새 사실을 만들지 않는다. 큰 폭의 의미 병합은 계속 보류한다.

## 7. 4.6 — 약속·상태의 진행 이력을 관리

상태: **VERSION_ASSIGNED_PLAN / 미구현**. 현재 코드에 맞춘 개별 보완을 작업 명세로 삼지
않고 아래 동작을 먼저 확정한다. 실제 저장 형식·필드·기존 소유자 연결은 착수 시 정한다.

1. **대상과 이력:** 같은 약속의 생성·진행·부분 이행·완료·취소·변경·회상을 이어 관리한다.
   사건 발생 시점과 언급/기록 시점을 구분한다. 복합 약속의 일부 이행으로 전체를 종료하지
   않으며 반복 약속은 회차와 지속되는 의무를 구분한다.
2. **한 갱신 결과:** AI는 이번 확정 대화, 관련 기존 진행 상태와 근거를 보고 변화의 의미를
   판단한다. Go는 그 판단과 출처를 저장하고 요약·목표·최종 전달이 같은 상태 결과를 읽게 한다.
   상태 갱신에 기존 평론가를 활용하는 방향을 우선 설계하며, 추가 상시 AI 호출을 전제하지 않는다.
3. **회수와 현재 효력:** 과거 약속이 검색되면 그 대상의 최신 진행 상태와 근거가 함께 따라온다.
   완료 사건이 독립 벡터 검색에서 우연히 같이 선정돼야만 완료로 읽히는 구조에 의존하지 않는다.
   과거 약속은 당시 사건으로 보존한다. 기본 Go·전처리·출판사가 같은 상태를 소비한다.
4. **상태 종류:** 일시적인 위치/옷/행동, 지속되는 지위/소유/관계, 약속 이행, 개인의 믿음과
   실제 사실을 구분한다. 저장 행의 최신 턴을 모든 필드의 발생 시점으로 삼지 않는다.
5. **기존 자료 복원:** 새 저장부터의 개선과 이미 남은 open/옛 상태 복원을 별도 산출물로 둔다.
   관련 원문·요약·변경 이력을 대조하며 근거 없는 완료를 만들지 않는다. 전체 기억 초기화나
   사용자의 유료 재생성을 기본 절차로 삼지 않는다. 복원 결과의 출처와 불확실성을 보존한다.
6. **기존 lifecycle:** 완료 출력을 삭제하거나 리롤해 다른 결과가 확정되면 기존 교체 의미에
   맞춰 상태도 달라져야 한다. 분기 이후의 완료가 부모/다른 분기의 상태로 번지지 않아야 한다.
   이를 위해 새로운 출력 거부 조건이나 별도 턴/삭제 시스템을 만드는 것은 계획하지 않는다.

AI의 의미 판단 오류가 완전히 없어지는 설계는 아니다. 잘못된 판단의 근거를 추적하고,
수정된 상태가 소비 경로 전체에 일관되게 반영되는지를 성공 기준으로 삼는다.

추가 확정 방향: 이미 있는 현재 상태와 변경 이력을 활용해 **확정된 변경 한 건에서 관련
현재 표현이 일관되게 산출되는 것**을 구현 목표로 삼는다. AI가 `state_claims`와
`resolved_threads`를 독립적으로 모두 맞춰 써야만 상태가 동기화되는 의존을 줄인다.
요약에 완료가 있다는 이유만으로 모든 관련 의무를 닫는 방식이나, 나중 open이라는 이유만으로
과거 회상을 새 의무로 취급하는 방식은 목표 동작이 아니다. 개별 문구 예외를 늘리지 않는다.

### 구현 전 고정할 비교 사례

| 사례 | 기대 결과 |
| --- | --- |
| 약속 → 이행 → 나중에 회상 | 과거 약속과 완료 근거 보존, 회상으로 재개방하지 않음 |
| 복합 약속 일부 이행 | 이행한 부분과 남은 부분 구분 |
| 같은 인물과 유사한 새 약속 | 이전 완료와 새 약속 구분 |
| 반복 의무의 한 회차 수행 | 해당 회차 이행, 다음 회차/지속 의무 보존 |
| 취소·거부·변경 | 미이행/완료와 구분하며 사용자 선택 반영 |
| 완료 근거가 일반 검색 상위에 없음 | 과거 약속의 진행 이력으로 현재 효력까지 전달 |
| 요약에만 완료가 있고 옛 목표가 open | 기존 자료 복원의 대상과 근거를 설명; 새 저장 성공만으로 해결 선언하지 않음 |
| 인물의 오해·비밀 공개 | 실제 사실·누가 아는지·알게 된 시점 구분 |
| 완료 출력 삭제·리롤·편집 재생성·분기 | 기존 확정 출력/교체/세계선에 맞는 상태, 무관한 역사 보존 |
| 전처리/출판사 OFF·ON 및 실패 | 같은 상태 근거 유지; 본문 모델의 표현 품질은 별도 평가 |

먼저 고정 자료와 생산 경로 내부 검증으로 실패를 검출하고, 그 뒤 필요한 최소한의 실사용
검증을 진행한다. 세션별 유료 출력·삭제 반복을 구현 검증의 주된 수단으로 삼지 않는다.

### 4.6 내부 순서

기본 약속·상태 이력 → 기존 자료 복원과 삭제/리롤/분기 검증 → 이야기 시간 전달 → 선택형
신체 상태 순서로 진행한다. [신체 상태 계획](../../_archive/future-reference/4.1-9.0-integrated-roadmap.md#optional-body-cycle-46)은
유지한다. 그 기능 안에서는 생리·가임기·개인별 주기 판단을 먼저 하고 임신 가능성·확률 판정·
경과를 이어 다룬다. 기본 상태 관리가 불안정한 채 선택 기능부터 확장하지 않는다.
