# 오류 보고와 상세 로그

Archive Center 4.5.0의 오류 보고 기능 사용 안내입니다.

## 사용

1. 새 JS와 백엔드를 함께 적용한다.
2. 설정 → **오류·진단 보고서 → 상세 기록 켜기**. 서버 재시작은 필요 없다.
3. 문제가 발생한 작업을 진행하고 같은 창에서 **보고서 저장**을 누른다.
4. **상세 기록 끄기**로 기본 기록으로 돌아간다.

연결된 백엔드 프로세스 전체에 적용되므로 같은 서버의 다른 대화도 대상이다.
UI 변경은 DB/설정 파일에 저장하지 않으며 재시작하면 시작 설정으로 돌아간다.
창을 다시 열거나 새로 고침하면 서버의 현재 수준을 조회한다. 보고서는 다운로드 시점에
다시 수집한다. 연결되지 않거나 이전 백엔드에 제어 기능이 없으면 버튼이 비활성화된다.
변경 응답을 받지 못하면 성공으로 표시하지 않으며 새로 고침으로 확인한다.
문제 발생 전에 켜야 이전에 남지 않은 상세 과정을 확인할 수 있다.

Docker/systemd 등 시작부터 상세 기록이 필요한 환경은 백엔드 프로세스 환경 변수에
`AC_LOG_LEVEL=debug`를 지정한다. 기본값은 `info`; 잘못된 값은 경고 후 `info`다.
Docker Compose의 해당 서비스 `environment` 또는 systemd 서비스 `Environment`에
지정할 수 있다. UI에서 켠 기록도 기존 표준 오류 출력으로 나와 Docker 콘솔 로그에서
확인할 수 있다. Docker 실제 컨테이너 시험은 이번 검증에 포함하지 않았다.

## 기록 범위와 보관

| 수준 | 기록 |
| --- | --- |
| 기본 | 기존 오류, prepare/complete 요청 시작·종료, 기존 저장 수락 판정과 대상 턴, 워크플로 완료·실패 |
| 상세 | HTTP 처리 시작·종료, 현재 입력 개수·묶음 위치·판정 사유, 턴 위치 조회 전후, Host 인덱스, 단계별 상태·시간, AI 작업 시작·종료 |

기존 요청 ID를 기록에 연결한다. 진단용 ID/context는 턴 소유권 판정에 사용하지 않는다.
`turn request finished`는 HTTP 처리 함수 반환을 뜻하며 저장 성공의 증거로 취급하지 않는다.
저장 판정, 워크플로 완료/실패 및 기존 저장 오류를 함께 확인한다. AI 작업 시간에는
기존 재시도 정책의 시간이 포함될 수 있다. 진단 창에는 최근 오류를 보여주고 상세 정상
흐름은 보고서 파일과 서버 콘솔에서 확인한다.

이번에 추가하는 필드는 단계/개수/시간/코드/모델명 등 메타데이터다. 대화 원문, 기억 본문,
프롬프트, HTTP body/query, API 키는 추가 기록하지 않는다. 기존 오류 내용의 마스킹은 유지한다.
기존 Go 로그 회전(파일당 4 MiB, 현재+과거 3개)과 보고서의 파일별 최근 64 KiB 수집을 사용한다.
따라서 보고서는 최근 범위이며 무제한 전체 이력은 아니다. Docker 자체 로그 보관은 해당
Docker 설정에 따른다. 별도 메모리 이력·비동기 큐·DB 테이블·자동 업로드를 만들지 않는다.
JS의 기기 진단도 기존 40건 상한을 유지한다.
상세 모드는 로그 I/O가 늘어나므로 문제를 재현한 뒤 끄는 용도다. 파일 쓰기 실패는 채팅
실패로 전파하지 않지만 느린 디스크/콘솔의 대기까지 없다는 의미는 아니다.
