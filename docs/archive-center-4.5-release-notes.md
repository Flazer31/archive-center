# Archive Center 4.5.0

4.4의 기억 회수 폭·분류별 예산·묶음 전처리를 유지하면서, 기억의 문맥 보존과 동일 본문 공유를 보완했습니다.

## 기억 구성과 전달

- 기억 선정 전에 주체·대상·관계 방향·조건·범위·부정을 함께 읽도록 구성합니다. Go 기본 선정과 전처리 1차·보완 검색·2차 및 최종 전달에 적용합니다.
- 규칙의 범위·예외·인용만 골라도 원래 규칙과 명시된 조건을 함께 전달합니다. 관계 값이 숫자 조각으로 나뉘던 경우도 원래 주체·관계·값을 제공합니다.
- 같은 원자료 요약의 파싱 표현, 같은 요청의 동일 객체·설명문, 떨어져 배치된 같은 규칙의 공통 본문을 재사용합니다. 개별 기억 ID·출처·시점·보유자·공개 범위는 유지합니다.
- 실제 증가한 문자 비용을 예산에 반영합니다. 의미를 보강하면 길어지는 항목도 있으므로 전체 토큰 소비 감소를 보장하지 않습니다.
- 페르소나 캡슐의 개인 경험·명시된 감정·출처를 한 회상 문맥으로 읽고 원근거를 보완 기억으로 연결합니다. 기존 캡슐 생성·연결 방식은 유지합니다.
- 전처리 기본 지침의 담당 범위, 근거와 해석, 추가 질문, 2차 전체 선정과 이유 재사용을 명확히 했습니다. 저장한 사용자 지정 프롬프트는 덮어쓰지 않습니다.

## 시간·턴 준비·진단

- 같은 요청의 문장 분석과 읽기 문안을 재사용하고, HUD와 전처리 내보내기에 기억 조립 상세 시간을 추가했습니다. 모델 대기와 Go 후보 구성 시간을 구분할 수 있습니다.
- 입력 확인 통신의 제한 시간을 응답 본문 읽기까지 유지하고, 실패한 준비 요청이 재시도를 붙잡지 않게 정리했습니다. 전체 전처리·평론가의 기존 긴 처리 정책은 유지합니다.
- 공식 현재 채팅 목록을 우선하고, 최신 턴만 필요한 조회에서는 전체 기억 본문을 읽지 않습니다.
- 기존 판정이 본문 편집이면 ‘출력 수정 반영’으로 안내합니다. 교체 저장 실패 원인은 HTTP 200 응답이어도 진단에 남깁니다. 여러 입력을 한 턴으로 묶는 기준, 리롤·편집·삭제의 저장 원칙은 유지합니다.
- 설정의 **오류·진단 보고서**에서 상세 기록을 켜고 끄며 최신 보고서를 저장할 수 있습니다. 시작부터 기록하려면 `AC_LOG_LEVEL=debug`를 사용합니다. 기본은 `info`이며 UI 변경은 프로세스 단위 임시 설정입니다.
- 재처리 예약이 없는 `record not found`를 정상 대기로 처리했습니다. 실제 DB 오류는 계속 기록합니다.
- 출판사 OFF에서 미사용 main/supervisor 모델 누락을 전체 설정 동기화 실패로 표시하던 문제를 수정했습니다. 저장된 키와 다른 역할의 준비 상태는 유지합니다.

## 설치와 업데이트

- POSIX 설치 명령이 끝나면 감시용 대기 프로세스를 회수하고 설치 준비 중 종료·신호 처리를 보완했습니다. 마지막 오류 로그와 종료 코드를 유지합니다.
- 기존 한 줄 신규 설치와 Windows `01_start_archive_center_windows.bat` 진입점을 유지합니다. 기존 설치는 업데이트 경로를 사용합니다.
- 관리형 백엔드는 UI의 **업데이트 확인 → 지금 업데이트**로 패키지를 교체합니다. 개인 설정·데이터·저장된 서비스 포트는 관리 파일 교체 대상에서 제외됩니다.
- **RisuAI에 등록된 JS는 백엔드 업데이트 버튼이 자동 교체하지 않습니다.** 플러그인 업데이트 또는 4.5.0 JS 가져오기도 함께 진행해 주세요.
- 이 조립 개선을 적용하기 위해 기존 기억을 초기화하거나 콜드 스타트를 다시 할 필요는 없습니다.

검증 범위는 [4.5 배포 기록](archive-center-4.5-release-verification.md)을 참고하세요. 완료된 약속과 개별 상태의 실제 효력 시점 정리는 이후 4.6 범위입니다.
