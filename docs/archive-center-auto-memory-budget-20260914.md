# 자동 기억 예산 배분 복원 — 4.4.0-test.16

2026-09-14. 사용자 승인: 자동 모드에서도 예산을 나누어 적절하게 배치하도록 수정.

## 원인과 수정

4.3.1과 test.15에서는 직접 근거를 일반 기억보다 먼저 삽입하고, 자동 모드의 직접 근거 상한을 전체 기억 예산으로 사용했다. 직접 근거가 풍부하면 검색된 요약·인물·관계·세계·목표가 최종 주입에서 모두 빠질 수 있었다. [수정 전 재현](../../_diagnostics/20260914-direct-evidence-budget/README.md).

활성 Go 소스의 `prepareTurnPriorityDeliveryCaps`와 `buildPrepareTurnPriorityMemoryDeliveryPlan`을 수정했다. 등록 `/prepare-turn`은 이 priority 경로를 사용한다.

1. 자동 모드의 초기 배분은 기존 UI 기본 비율을 따른다. 전체 18,000자일 때 직접 근거 3,500, 비밀 보호 1,200, 사건·최근 기억 3,500, 인물 2,500, 주관 기억·관계 3,000, 세계 2,500, 목표 1,800자다. 전체 예산이 달라지면 비례 배분한다.
2. 모든 분류가 초기 배분을 사용한 뒤 남은 공간을 공유한다. 공간 때문에 보류된 보호 안내와 일반 기억을 다시 검토한 후 추가 직접 근거를 담는다. 기존 분류별 핵심 순회와 관련성 순위는 유지한다.
3. 긴 항목도 빈 공간이 충분하면 원문 전체로 다시 담는다. 첫 배분에 못 들어갔다고 영구 제외하거나 문장을 잘라서 맞추지 않는다. 재배분으로 선정 시점이 바뀌어도 최종 분류 내 읽기 순서는 유지한다.
4. 집계는 최종 결과를 따른다. 첫 배분에서 보류됐다가 전달된 항목을 제외로 중복 집계하지 않는다. `reserved_chars`는 초기 배분, `borrowed_chars`는 그보다 더 사용한 문자 수다.

수동 예산과 정상 AI 추천 내용·순서, 기존 AI 추천의 예산 초과 허용 처리는 바꾸지 않았다. 전처리 추천 없음/실패는 개선된 Go baseline을 그대로 사용한다. 검색 후보 수·저장 중요도·최신성·비공개 범위·DB·출판사·평론가·턴 인식·삭제·리롤·추론 설정·토큰 절감 실험은 이번 수정 대상이 아니다. 직접 근거의 화자/주변 문맥 보충, 저장 시 발췌 자르기도 변경하지 않았다.

## 검증

증거: `../../_diagnostics/20260914-direct-evidence-budget/`.

- 수정 전 생산 함수에서 직접 근거가 다른 분류를 밀어내는 신규 회귀 실패를 기록했다(`regression-before.txt`).
- 신규 생산 회귀는 OFF·정상 추천·추천 없음·실패·일부 정상 추천의 5가지 상태, 긴 항목/빈 분류의 공간 재사용, 예산 크기 변경, 수동 상한, 원래 순서, 출처 턴, 중복 집계, 실제 벡터 결과 수화부터 최종 payload lane까지 검사한다.
- 이전 재현과 동일한 10개 조건을 재실행했다(`fixed-results.json`). 자동 OFF/추천 없음/실패는 일반 기억 **0개 → 10개, 다섯 분류 모두 전달**. 수동 모드 5개 조건의 관찰 결과는 이전과 완전히 같다.
- 자동 OFF 최종 사용은 **17,955 → 17,834자**다. 직접 근거는 16,575자까지 재배분받았다. 이 자료에는 일반 기억이 약 1,200자만 있으므로, 전부 전달한 뒤 남는 공간을 추가 근거에 쓴 결과다. 직접 근거가 항상 3,500자로 고정된다는 뜻이 아니다.
- 전체 Go 검사: **5,932 통과 / 14 건너뜀 / 실패 0**, 패키지 단위 36개 통과. 신규 테스트/하위 테스트 14개를 포함한다. 외부 DB를 필요로 하는 선택 검사 등은 건너뛰었으며, 실제 유료 LLM·사용자 MariaDB/Chroma를 호출하지 않았다.
- 기존 전처리 AI 추천 순서·예산 처리, 일반 기억 검색 회귀도 전체 검사에 포함한다. 자동 예산 수정으로 개별 사용자의 출력 품질까지 검증했다고 주장하지 않는다.

최종 검토에서 처음 배분에 못 들어간 동일 근거 두 개 중 하나가 재배분으로 전달될 때 나머지 중복 제외가 로그에서 누락되는 경우도 재현했다. 기존 중복 판정은 유지하고 재배분 시 진단 집계를 바로잡았으며 해당 회귀를 추가했다.

런타임 변경은 Go 한 파일 +125/-42줄, 회귀 테스트 별도. 런타임 JS +0/-0. 기존 작업 트리의 다른 변경은 보존했다.
