## 2. 계산 경계와 연결

| 구분 | 요청 안에서 재사용할 내용 | 질문마다 다시 판단할 내용 |
| --- | --- | --- |
| 자료 준비 | 공개 요약·어휘·원문 사실 분리·출처 식별·인물/관계 등 고정 자료 | 새로 발견한 자료의 최초 준비 |
| 기본 비교 | 현재 입력·기존 맥락의 어휘 비교, 같은 인물·공개 범위의 해석, 기존 통계 근거 | 추가 질문의 일치·의미 점수·발견 경로 |
| 후보 구성 | 준비한 사실 및 원래 출처 순서 | 질문별 검색 결과의 포함·정렬, 최신 출처 판정 |
| 담당별 입력 | 1차 자료와 기존 AI 선정 | 기존 보완 검색 합류 규칙에 따른 2차 자료 |
| 최종 전달 | 준비된 후보·출처·기본 점수 | AI 추천 또는 Go 선택, 기존 문자 예산 적용 |

`prepare_turn_request_projection.go`는 **한 prepare 요청만 소유하는 계산 자료**다.
세션 캐시나 영구 저장소가 아니다. 원본과 질문별 관측을 별도로 보관한다.
같은 원본 변환·기본 비교를 재사용하고, 새 질문의 근거와 점수는 다시 계산한다.
공개 범위별 판단의 재사용 키에는 관점이 구분되며 공개/비공개 판정 함수는 그대로다.
캐시한 원본 map에서 표시용 필드를 제거할 때는 복사 후 처리한다.

`prepare_turn_assembly.go`는 최초 조립 중 고정 자료를 원래 순서의 조각으로 준비하고
`supplementProjection`을 제공한다. `group_turn_prepare.go`의 실제 추가 검색 콜백은
전체 `buildPrepareTurnAssembly`를 다시 호출하지 않고 검색 결과 참조와 질문별
selection을 이 projection에 전달한다. 질문을 합치거나 담당의 읽기 범위를 좁히지 않는다.
새 질문의 근거로 오래된 world rule이 다시 후보가 되는 경우도 검사했다.

기존 요청 내부 조립 mutex는 유지한다. 외부 검색은 기존처럼 겹쳐 진행하고 질문별 후보
판단은 그 뒤 직렬로 실행한다. 이번 변경을 후보 조립 전체의 병렬화로 설명하지 않는다.
그 뒤 기존 `runMultiAgent`의 공통 후보 합류 → 담당별 2차 입력 → AI 추천/Go 대체를
유지하고 `finalizePrepareTurnPriorityMemoryDeliveryPlan`이 준비된 후보를 사용한다.

추가로 프로파일에서 최종 전달 후보 하나마다 전체 문장을 다시 만들어 글자 수를 세는
비용을 확인했다. 같은 헤더·줄바꿈·한글/이모지 문자 수를 증분 계산하고 실제 문장은
최종 단계에서 만든다. 자동 배분·남는 공간 재배분·수동 상한·AI 선정 순서는 유지한다.
